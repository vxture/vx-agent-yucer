# 战略预期、规划承接与承诺兑现

## 目标

战略提出经营预期，销售规划判断可行性并核定具体目标，拆成季度与销售区域，承诺达成核对兑现。
公司目标仍可独立发布；未承接战略的目标保留，不强制挂靠战略。

## 模型及边界

- 战略版本维护预期收入、渠道建设数、标杆案例数及兑现标准；预期不是正式销售配额。
- 公司规划核定年度承接值、负责人和依据；区域规划继承公司发布版本后分配季度、区域、责任人。
- 所有关联使用 UUID。编号、名称、版本号只用于展示；承接保留来源发布快照。
- 战略金额轴与地域金额轴解释同一公司目标，不相加；同币种已承接收入不得超过公司目标。
- 区域季度承接总和不超过对应目标，单项分配总和不超过公司核定值；待分配显式保留。
- 自动拆解使用区域收入及季度目标权重，余额按最大余数法保留到分/整项，不强制超出容量。
- 跨年战略按日期重叠提出年度建议，用户核定年度值；不自动修改其他年度或历史版本。
- 发布快照不可写；新战略版本不会自动替换旧来源，规划调整通过草稿发布，差异可追踪。
- 收入实际使用明确战略/活动归属的已成交商机金额，按成交日期、币种、地域与周期过滤、UUID 去重。
  不将客户匹配、商机预计金额、会计确认收入或合同额混为一谈。归属冲突或缺失事实显示未知。
- 渠道与案例独立维护兑现标准，通过凭据逐项登记；凭据去重、追加存储，撤销保留历史。
- 完整跨域看板仅向工作区范围且具备战略、规划和达成读取权限的用户开放；不扩大原有权限。

## 实施与验证

实现已完成，追踪 Issue #664。数据库增量 0122、0123；生产需分别经过数据库升级和应用部署的 owner 审批，上线结果以发布记录为准。

- 公司核定、区域分配、兑现凭据使用 DS 卡片与 512px 抽屉；支持自动分配及手动选择区域/季度、调整负责人、添加/移除分配。
- 已结案季度在界面、领域层与数据库发布校验中冻结分配与来源；年度核定依据和未来周期仍可修订。
- 本地全量应用测试：3,024 通过，465 项需数据库测试按配置跳过，无失败；最新补充的来源/缺失信息校验与规划服务测试 36 项通过。
- 从 main 既有 123 项增量升级、以及空库全新执行 125 项增量均成功；两库分别 463 项数据库测试全部通过，结构一致。重复执行为 0 项新增、125 项已记录。
- TypeScript 类型检查、生产构建、DDL/Prisma/列锁检查、文档编号、80 页面及 71 并行路由槽表面检查均通过。
- 浏览器验证：战略、规划、达成三处展示一致；核定抽屉宽度 512px；草稿保存/重开/放弃不改正式版本；渠道凭据登记及撤销均生效，过程无运行时异常。
- 演示样例仅写入本机内存演示仓储，不向生产插入模拟战略或业绩。

## 用户操作

1. 战略草稿设置经营预期和渠道/案例兑现标准，发布战略。
2. 销售规划调整公司草稿，在“战略承接”核定具体值和负责人，检查后发布公司规划。
3. 基于公司发布版本拆解区域，自动填入季度与区域分配，再按实际资源修正、发布。
4. 承诺达成查看战略兑现：收入来自已成交商机；渠道与标杆用凭据逐项登记。错误凭据撤销留痕。
5. 战略修订或规划调整均另建草稿，新版本发布后生效；历史来源不随之静默变化。
