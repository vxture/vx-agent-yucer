状态：2026-11-26，SC-00–SC-04 已完成并合并；owner 已批准，v0.1.148 已上线且业务只读验收通过。窄屏管理抽屉发现裁切，修正预览通过，尚未授权后续发布；不将整轮视觉验收标为全部通过。

## 业务决定

- 战略是宏观牵引，可大可小、可跨年，也可聚焦某季度的品牌或渠道建设。
- 公司销售规划按年度核定可执行的正式承诺，包含责任人、季度节点、行动及支撑。
  已生效发布版是承诺达成的目标依据；草稿、战略预期和预测各自独立。
- 周期与区域是同一公司目标的两条分配轴，不能相互累加。
- 重点客户、储备商机、新客、渠道及标杆是主目标的强关联支撑，也可设辅助目标。
  不把渠道、客户或案例跨战略的数量相加后称为公司去重总数。
- 当前去重按已登记业务对象身份。同名的两个独立登记对象仍为两个；同一对象被重复引用
  只计一次。不按名称、信用代码相似度或模型猜测自动合并。
- 信用代码完善、智能登记查重与重复对象合并另作后续任务，本次不实施。

## 现状证据

线上v0.1.147：市场战略“销售规划已承接6/6”混合多个年度；2026当前版仅承接1份、
营收100万元，2027当前版承接5份、营收2,000万元。现有2026区域草稿只能拆解公司承接，
其存在会隐藏公司调整入口。底层支持多战略，不能将问题归因为只能选择一份战略。

本轮保持共享单草稿、发布快照、权限服务及历史边界，不自动丢弃区域草稿，不回写生产记录。
新增入口必须说明已有草稿的实际阶段和可选处理路径；不能承诺尚未实现的跨阶段无损转换。

## 验收要求

- 同一战略跨两个年度、不同版本、草稿／预约／关闭状态不串用。
- 已选战略数与指标数分别显示；专项数量不冒充对象去重数。
- 同币种战略营收份额与年度承诺对照，金额精确到分；明确0、缺值、超额和异币种分开。
- 多战略建议不得因旧目标已占满而静默变成0；跨年战略由年度规划明确核定，不按天自动摊派。
- 公司与区域草稿分别编辑自己的内容；历史和受限账号不出现可执行调整入口。
- 客户同名不同ID保持两个、同ID多处支撑只计一次；缺业务来源不伪造实际达成。
- 桌面、侧栏、手机和全局字号下复用DS token；不增加自定义颜色或尺寸。
- 本地、CI与真实业务验收分开记录，发布等待用户明确指令。


## 本轮交付与使用路径

- 市场战略：摘要改为“已纳入年度规划 N 项战略”，不再以跨年度 6/6 暗示本年全部目标
  已承接。卡片标签增加年度，悬停提供精确销售规划版本及已选指标数。
- 销售规划：承接区显示 Y年度／战略数／指标数；“调整承接”就近进入公司编制，
  一个抽屉集中选择多战略、多指标，显示战略原预期、本年承担值与负责人。
- 年度金额：同币种年度营收 = 战略承接份额 + 其他经营目标。战略份额超额、缺值，
  或缺同币种公司年度目标均先提示；新建议不再被旧预算静默截成 0，跨年值不自动摊派。
- 草稿：公司草稿可以续编；区域草稿明确保留公司发布基准，提供继续区域编制／草稿管理。
  不自动覆盖、不转换草稿；放弃仍经过原有明确确认。保存与预览不改变当前正式承诺。
- 目标支撑：公司／区域目标下呈现登记客户数、新客目标、商机储备目标、专项承诺条目、
  有负责人与日期的行动节点比例。客户入口保留年度、版本与区域；专项入口展开承接明细。
  缺失目标显示“待核定”，不显示虚假 0；不同币种不混合。
- 承诺达成：原已生效目标与证据链继续使用；渠道／案例当前明确标记“凭据数”，
  不将专项跨战略相加视为公司去重数量，不把客户计划或商机储备当作已成交收入。
- 展示：采用现有 DS 组件、字号、色彩及间距 token。桌面保持负责人居右；窄屏抽屉
  金额与负责人分行，保留选择占位缩进及右对齐，避免挤掉数字。

## MVP 边界与后续

- 支持跨战略复用同一登记对象；相同 ID 在客户支撑中去重，不同 ID 同名不自动合并。
- 渠道／案例仍是凭据台账，尚无“凭据关联已登记客户／伙伴”的完整结构，不能宣称
  已实现专项主体去重。此次用明确标记及逐项核对避免误导；主体关联另作后续能力。
