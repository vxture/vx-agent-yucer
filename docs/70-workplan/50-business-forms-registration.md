## 表单统一规则

| 检查项 | 实现 |
| --- | --- |
| 字段标签 | DS body-small / muted-foreground，默认密度 12px |
| 字段内容 | DS body / foreground，默认密度 14px；包括周期与人员选择结果 |
| 单行控件 | 保持 DS 32px 高度；多行描述保留自然高度 |
| 操作按钮、筛选 | 保持原 12px 规则，主要提交按钮可 14px |
| 短字段 | 共用 DS FieldGroup，按实际内容宽度三列、两列、单列适配 |
| 长字段 | 描述等内容独占整行 |
| 客户字段顺序 | 基础资料 → 客户定位 → 区域归属 → 经营信息；轻分隔线分组 |
| 创建与编辑 | 客户继续共用 AccountFields；战略及其他资料页复用 FormPage / FormFields |
| 编号与负责人 | 客户保存后自动生成编号，当前用户为默认负责人 |

不将操作行或筛选的字阶整体放大。

## 客户登记流程

名称与定位 → 智能填写 → 对话补充或直接修改 → 核对资料 → 确认登记 → 客户详情。

- 只使用用户本轮明确提供的事实；分类匹配工作区已有选项，缺少的信息可继续沟通。
- 省份可在区域配置唯一匹配时补入销售区域，不覆盖已填区域。
- 相似客户仅在当前工作区且可读取时提示，避免重复登记。
- 战略客户沿用经营目标必填规则，普通客户的非必填字段可暂空。
- 智能整理无工具执行和客户写入能力；最终确认才调用原 createAccountAction。
- 失败保留原始提问和表单；重试复用未回答的消息。取消核对可继续编辑。
- 模型统一复用既有 runCopilotTurn → AtlasClient，使用 drafting 档位、现有 endpoint
  路由与计量。真实登录会话传递用户票据，沿用 Atlas OBO；不增加模型供应商配置。

## 能力优先与公开资料查询修正（2026-11-15，v0.1.94 已发布）

线上反馈暴露了实现缺口：客户登记 frame 只允许最新消息原文，`draftOnly` 关闭了
工具面，解析器也只接受原文片段。因此真实 Atlas 回复仍会拒绝公开资料查询；
上一轮模拟集成验证没有覆盖这一真实使用场景。

本轮按 owner 最新要求采用全站能力优先：

- 共用提示词先完成业务工作，主动调用工具获取事实，保留上下文，减少重复追问；
  页面上下文不作为拒绝跨模块协助的理由。可选规划假设可形成标明假设的草稿。
- 继续复用现有 Atlas 及 Runos，不新建搜索服务或直连模型供应商。
- 新建客户允许在同一回合使用 Runos 只读查询和技能指导。获取完整注册 schema，
  并固定当次解析版本；技能指导本身不冒充查询到的企业事实。
- 查询结果可补全空缺企业字段，展示成功查询结果中的来源链接；已填写字段优先。
  目标、级别、期间及执行节奏来自业务人员，查询不替其制定。
- 多轮对话可使用此前明确提供的事实补空缺，不用历史资料覆盖后续手动修订。
  客户仍从原核对流程最终保存。
- 通用助手页面入口补传真实用户票据；SSE 接入同一工具循环，不能因传输方式
  丢失研究能力。旧逐 token 实现作为无 Runos 依赖时的兼容路径保留。
- 通用助手同样获取平台注册的工具参数 schema，避免只给名称和空参数对象。
  单项契约暂时不可读时保留发现信息，其余工具继续可用；已解析的非只读操作不直调。
- 默认工具往返预算从 4 轮增至 8 轮；研究入口不再额外截断为 6 项能力。
  实际能力以平台当次 discovery/resolve 返回为准。
- 模型身份来自 Atlas 实际返回的 modelCode，不让模型猜测或拒绝身份问题。

线上只读诊断确认 Atlas 和 Runos 已配置且可达；这不能证明某个搜索能力已登记
并授权，也不能代替真实企业查询验收。本机没有真实平台登录票据与模型连接，
本轮真实联网企业查询仍需部署环境核验。

验证：完整离线回归 3389 项，2938 通过、451 项数据库测试按环境跳过、0 失败；
补齐模型身份与 SSE 测试后，114 项针对性测试全部通过。正式构建、类型检查、
