## DD-00 审查证据

- `lib/functional-domains.ts`：当前 deployment 三入口、winLossReview 在 position，目标四入口不同。
- `/named/page.tsx` 过滤非 standard；`NamedAccountActions` 调用 `designateAccountTier`，
  操作会改变客户级别，与周期纳入不同。
- D2 `plan-model.ts` 已有 CustomerBudget/Contribution/TeamAllocation/PlanAction；优先复用。
  当前未独立保存“本期重点”标记、逐客户团队等语义，缺字段不得仅靠 UI 猜测。
- `/planning` 已发布公司/区域工作流、`strategy-handoff-panel` 及规划源可保留。
- 承诺达成已有三视图与版本基准，历史预测不是赢丢原因分析。
- `/winloss` 以 pending/allClosed 和原因登记为主，表单 `startTransition` 中脱离 Promise，
  回归需覆盖等待/异常/重试，不能只迁菜单。
- `review-draft.ts` 有逐单事实底稿，store 是一商机一复盘；集中分析仍需授权聚合读模型。
- `deploymentFacts` 仍围绕旧目标和 territory，域级缺口须改用当前已发布规划与实际地理配置。

本轮为源码核对，未重新操作生产账户或创建经营数据，不宣称现有 UI 已按新规范验收。

## DD-01 一期实现与验证

- 作战部署入口顺序先改为销售规划、现有战略客户、承诺达成。旧 `/named`、`/planning`、
  `/attainment`、`/winloss` 路径不变；重点客户切换和赢丢归属继续由对应业务批交付。
- 域首页复用 `ViewHeader`/`PageActionButton`、`CollectionToolbar`、DS `MetricCard` 与
  标题帮助抽屉。年度明确选择，规划/达成深链携带年度，统计深链固定当前修订 UUID。
- 删除旧目标表与全部 territory 比较得出“未覆盖区域”的总览口径，改用现有
  `readSalesPlan` 的权限及来源门禁，并只返回摘要，不向浏览器传递完整规划内容。
- 当前生效版、草稿、预约发布分开；公司修订沿用区域内容时同时标明原区域版本。仅发布公司
  目标显示待拆解区域。无发布、范围/权限不足和读取失败分开，不生成零覆盖结论。
- 统计纳入区域、按 UUID 去重的部署客户、纳入区域待定责、客户待排行动；最后一项只表示
  当前发布快照中没有明确客户行动，不推断客户实际未经营。人数、金额等未核定指标不虚构。
- 现有模块已使用 `ModuleHeadline`；本批集中修正域级总览，没有提前将区域编辑、客户分级
  或原复盘清单宣称为新业务。助手仍按已有路由映射定位，具体草稿任务在 DD-02–05 接入。
- 本地新增 10 项读模型回归覆盖 UUID 去重、草稿/未来版隔离、公司/区域版本继承、公司未拆解、
  工作空间/年度隔离、权限/范围门禁、来源权限、仅行动关联客户的读取权限、读取失败和结期。本地全量回归 3165 通过 / 479 条环境跳过，43 项定向检查通过；无数据库变更。
  隔离演示浏览器验证 1440/1024/720/390px 无横向溢出、输入与按钮均 32px、帮助抽屉
  为 DS md（实测 512px）、未发布/无效年度与年度深链正确。最终构建和 CI 记录在本批 PR /
  #697；尚不代表已上线或真实经营验收通过。

## DD-02 实现与验证

- 保留年度工作区与现有版本服务。未发布不再显示仿正式的空目标；默认生效版只读，
  公司/区域草稿分别标识，发布继续保存→检查→明确确认。提交增加同步防重锁。
- 区域卡片与清单共用同一读模型、全站显示模式、区块工具行、DS 表头/排序与人员组件；
  搜索区域/省份、按纳入状态筛选。卡片按实际内容容器弹性排列，不按浏览器总宽度推测侧栏。
- 区域负责人显式设置；客户、团队、行动分别以同级信息卡展示，帮助归入标题抽屉。
  只读规划隐藏未填前提和说明；区域继承版本单独标识，不暗示公司修订已重新发布区域部署。
- 客户按 UUID 跨预算/行动去重，包含仅有行动的客户；年度支撑只汇总关联该目标的同指标、
  同币种贡献，不叠加季度。未核定不作零，超出支撑不隐藏负缺口。公司余额排除未纳入区域，
  未填/异币种区域保留待核定，金额按分精确计算。
- 年度、修订 UUID、区域和期间写入深链；保存后继续查看同一草稿，刷新/回看不丢位置。
  区域清单无真实批量动作，不增加选择列；名称和操作列打开详情。
- 顶部智能填写与右侧助手共用现有会话框架，沿用 Atlas/Runos OBO、计量和审计。
  本批支持当前公司/指定区域草稿的年度四类目标及规划前提回填，沿用表单的自动阶梯/季度规则。
  不把“生成文本”当作保存成功；完整字段校验通过才回填，之后仍需人工保存/发布。
  会话绑定工作空间/操作者/年度/草稿 UUID/编辑令牌/区域；服务端检测并发保存，客户端检测
  请求期间的人工变更，拒绝陈旧回填。切换草稿上下文重置会话，保留失败重试。
- 来源权限补齐“仅行动关联客户”和“仅区域负责人”情形，防止无预算/团队时绕过来源门禁。
- 自动化及浏览器证据记录于本批 PR 和 #697。隔离演示完成新建公司→自动拆分→保存→检查→
  发布 V1→区域拆解→详情刷新→发布 V2；验证 1440/1024/720/390px、跨模块模式记忆。
  模型测试使用协议夹具，不宣称真实模型生产验收；无数据库结构变更，尚未部署。
  本地全量 3181 通过 / 479 环境跳过 / 0 失败；规划与来源/助手定向 130 通过 / 38 数据库跳过。
- 审查复测 25 项通过；类型检查、生产构建及文档/页面守卫通过。质量分析提示逐项修正；
  季度匹配改用固定分支，不使用动态正则。产品方案导航仅组装固定站内路径与编码 UUID，
  展示名称及渲染标识由原生元素承载。最终安全/质量检查结果以 PR #700 和 #697 归档为准。

- 一条战略预期核定进公司目标，自动季度分解，检查分析、公司发布，再基于同一公司版本区域拆解。

- 公司/区域/个人受限读取在服务端收窄；不先取整版客户/成员敏感数据再前端过滤。

### DD-04 / DD-05

- 赢单/丢单/放弃独列；未关闭不能登记赢丢；原商机一份复盘，两处入口一致。
- 登记 Promise 等待、失败与重试、已有记录重开、原因字典停用/未分类/缺原因明确。
- 汇总样本与钻取清单一致；按关闭时间，不按复盘录入时间冒充成交期；赢单率分母与放弃排除可解释。
- 多方案/多市场的同一商机不重复计金额，无法可靠分摊不展示加总榜单；异币种不隐式换汇。
- 反馈打开正确对象并形成可复核草稿，未保存/已保存/已发布分别提示，旧归因与发布版不改。
