| 身份层级 | 标题／标签一行，编号／周期等元信息一行，正文在虚线以下 | 业务卡片沿用两层身份结构；对比表、进度和证据保持各自形态 |

| 关联摘要 | 可用宽度内尽量展示完整条目，隐藏项显示 +数量，浮层一行一项 | 适用于战略、区域、客户和方案等多值引用，长说明走摘要／详情 |
| 业务链接 | 图标 primary-text，浅色 opacity-muted；文字中性，hover／focus 使用 link-hover | 统一详情和原模块入口，图标与名称为同一点击区域，保留无图标链接提示 |
| 编号与时间 | 业务编号、标准周期、版本身份分别表达；不显示 UUID，不猜历史日期 | 复用当前对象编号和 Y／Q 周期，规划区分公司与区域发布来源；不照搬 STR 改号 |
| 数据状态 | 真实零、未明确、无权限、加载中和失败分开；空集合不说全部完成 | 分别定义四页的零缺项文案、空分母、不可汇总及来源不可用状态 |
| 表格与浮层 | 表头、数字与单位对齐，真实数值排序，未知置底；浮层有正常宽度与视口约束 | 清单和卡片口径一致；证据能直接到业务记录，避免多层空跳转 |
| 表单与抽屉 | 短字段按需宽度，说明自动撑高；底部安全区，按钮尺寸明确 | 重点检查承接、客户贡献、行动、版本发布、报送和复盘抽屉 |

全部复用 DS 组件和语义 token。主要动作默认14px、次要12px，常用操作保留32px点击高度；
尽量同一行同尺寸，允许有业务依据的例外。未发现必须新增的 token；实施若有缺口须明确报告，
不能自行写死色值、字号或间距。资源到位批次144仍未实施，不把计划需求误称实际到位进度。

## 四板块的优化重点

| 板块 | 标题概要候选 | 内容与操作重点 |
| --- | --- | --- |
| 销售规划 | 当前公司／区域发布依据、纳入区域数、待核定目标或待定责区域、草稿状态；最多三组 | 战略承接轻量展示；四类目标重点突出；公司与区域操作分开；草稿预览和继续编辑可发现 |
| 重点客户 | 本期已部署客户数、贡献待核定数、需关注数；需要时用已安排客户行动数替换 | 客户名称／编号／级别层次明确；营收贡献、关键人、决策链与下一行动易读；纳入不等于修改客户级别 |
| 承诺达成 | 正式目标、实际完成／达成率、剩余缺口；目标或事实未知时分别提示 | 目标／实际／预测清楚区分，数据时点和版本可查看；直接钻取证据；报送入口按状态出现 |
| 赢丢复盘 | 当前期间已结束样本、待复盘、复盘完成度；结果分类保留在分析／清单 | 清单便于处理，原因分析便于比较；登记／查看按状态；直接打开逐单底稿和对应业务记录 |

候选需在页面预览中确定最终三组信息，不为了文案新增无依据指标。尤其：

- 公司修订可沿用旧区域发布内容，不能显示为本轮已重新发布；不编造“逐区域发布数”。
- 公司／区域／季度不重复加总；四类目标不同单位，毛利率不与金额或客户数相加；跨币种不合计。
- 客户贡献是规划，成交是事实；缺联系人、缺角色和缺决策链互不替代。
- 历史目标、历史报送与当前商机分别说明；历史目标不冒充历史业务快照。
- 赢率按 won/(won+lost)，主动放弃独列；复盘完成度按当前合格样本，缺关闭日期单列。
- 摘要服从期间／版本／授权范围；搜索是否影响摘要须明确，清单匹配数与整体概要不能混淆。

## 集中验收口径

- 逐页覆盖主入口、卡片／清单、详情、草稿／历史、抽屉和兼容入口，不只检查四个首页。
- 深浅主题、全局字号、密度，侧栏宽／窄／关闭；长名称、多引用、多指标和正常浮层宽度。
- 1440／1024／700／390／320px，实际内容容器变化、表格内滚动及底部安全区域。
- 空数据、真实0、未明确、读取失败、权限不足、过期草稿、并发修改及历史只读。
- 保存失败保留输入，必要字段在保存阶段提示，重复点击不重复写入，跨页保留同一版本上下文。
- 浏览器效果、自动化测试、真实登录业务验收、生产发布分别标记，不互相替代。
- 发现需要新增 DS 能力、迁移或实际业务数据写入时如实列明；不预先假设需要改库或发布。
