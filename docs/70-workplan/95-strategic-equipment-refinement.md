## SE-01 设计与验收范围

- 市场覆盖沿用细分市场条件匹配规则；显式归属另行识别，不把归属数冒充匹配数。
- 市场金额仅统计该市场匹配客户的商机，按 UUID 去重，使用工作空间全局币种，不做隐式换汇。
- 区域收入目标来自当前生效的已发布销售规划，保留版本和目标行来源；不再任取旧 sales_target 首条。
- 区域成交额按商机区域、成交时间、同币种和目标周期筛选；缺金额、时间或必要归属时不伪造零值。
- 新口径有明确标识与比较基准，旧错误快照保留审计但不进入新趋势；不根据今天的数据伪造历史。
- 诊断窗口与展示单位一致；不同目标版本、市场条件或币种不串成一条趋势。
- 回归覆盖市场隔离、workspace 隔离、周期边界、币种、发布版本选择、缺失数据与服务权限。

本批不改变四个主体页面布局，不新增人工配置负担。代码、数据库、页面、发布分别记录实际验证结果。

## SE-02 设计与进展

- 根因：Accounts 状态确认只返回 `valid/next_check_at`，不刷新工作空间；access token 尚新鲜时直接复用旧票据。平台 #712 已发布并有真实生产复现记录，产品修正跟踪 #679。
- 进入产品的顶层文档导航、已有页面重新聚焦/返回前台、人工重新检查触发受控刷新，接收新验证票据的当前租户和工作空间。普通路由/业务请求和周期后台 GET 不强制续票；后台状态查询仍为 `active:false`。
- 前台同步复用 Redis 单 flight 和 CAS fence。刷新期间旧范围不可用于新的受保护业务；失败保留恢复凭据且显示可重试状态，不将取票失败解释为中央退出、未订阅或沿用旧身份。
- 获取新票据后先失效前后工作空间的本地角色/C2 缓存，再按实际空间重新查询准入和数据范围。页面比对身份、范围、治理角色和账号状态，发生变化时整体重新加载以丢弃旧 router/助手状态。原本未分配角色的普通成员仍使用 `sales_rep`；不更改管理员显式调整。
- OBO 调用绑定当前请求确定范围时的验证 claims；并发刷新或续期改变空间后不能向旧范围请求借用新空间票据。旧中央响应不仅不能覆盖新会话，也不能删除已经更新的会话。
- 角色/C2 缓存失效增加异步写入保护，避免在途旧查询在失效后重新填回缓存。恢复页保留重新检查，并可主动重新连接账号走正常授权流程，不要求全域退出。
- 本批不变更数据库、不新增平台字段、不读平台私有会话/数据库。生产真实非默认空间、跨产品账号 A/B、通知故障联合验收尚未完成，不提前关闭 #679/#677/#658。
