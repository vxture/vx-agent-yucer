## 一、交付目标与本轮基线

形成一条可真实使用的路径：首页看经营全貌 → 今日判断做决定 → 小聿分析与执行 → 打开任意相关业务页继续 → 核对真实结果。

- 首页为全局总览，只保留今日判断与机器人气泡两个主要操作，不设置三个页面导航按钮。
- 小聿是协作入口；当前任务是进入后的业务工作，不作为首页入口名称。今日判断为独立固定模板页，任务页按任务类型组装。
- 机器人与气泡是一个整体可点击、键盘可达的入口，气泡文案为“有事一起捋，有活一起干”。无默认语音播报。
- 同一工作空间、本人、持续任务和共用对话贯穿所有形态；页面、焦点、任务分别维护。
- 任务类型／名称／状态为一个32px组件组，统一 DS body-small=12px，共用底色、边界和分隔；名称仅以字重与颜色突出。
- 常规信息14px，辅助信息12px；标题56px。首页统计数字与第三行说明均缩进24px，与标题图标后的文字对齐。
- 复用127的标准／宽屏个人偏好、DS侧栏档位、滑动与中部伸缩、顶部避让、底部80px安全区；配置导航、大屏及门禁保留专用结构。
- 普通UI引用安装的DS组件与token；新增需求先查现有档位，缺少语义token时登记并告知owner，不私造数值冒充规范。机器人造型属于原创SVG插画，DS没有机器人／招手专用token，不影响通用布局token复用。
- 个人长期记忆继续作为后台能力；个人控制保留头像菜单。团队知识维护交给尚未接入的知识平台，不在工作页新增维护界面。
- Atlas使用已授权路由，Runos按需发现／加载能力；既有五条铁律、原服务、三种授权、来源／版本和真实回执继续生效。

## 三、每批交付与验收

### XC-01 共用面板与连续工作

- 把Header、当前焦点、对话、输入、更多操作作为同一组DS组合组件，独立页与业务页使用同一份任务状态。
- 顶栏56px；阅读区左24／右32px、消息间距16px；输入外16／内8px、主要动作14px／32px，无独立footer堆叠。
- 扩展结构化页面上下文：模块、列表／详情／编辑、对象UUID／版本、筛选／选中项、关联、字段规则与人工改动；不再只按URL猜测。
- 页面变化不重定向运行步骤；焦点可自动判断、调整、解除，也可为空，不作权限或操作授权。
- 复用现有Provider与服务端任务；页间续接保留未发输入，刷新恢复已同步的业务草稿、任务与真实进度。
  如需恢复未提交的输入，使用本人／工作区私有草稿契约，不把正文存入原本只存UUID的浏览器指针。
- 宽窄、展开／收起、切页和快速反向动画都不重建输入／任务；小屏只保留一个可操作对话输入。

出口：同一任务至少覆盖首页、小聿、今日判断、客户清单／详情／编辑、销售规划；失效来源及撤权反例同步通过。

### XC-02 首页与今日判断

- `/`实际显示总览；今日判断规划为独立地址 `/copilot/today`，小聿保留 `/copilot` 和 `?task=<UUID>`。
  这是计划中的路由，尚未创建；旧 `?view=judgements`、提案及对象查询链接逐条迁移，不能丢弃参数和任务。
- 首页经营指标、目标支撑、经营变化由受控域服务汇总，按真实权限决定本人／团队／工作区范围并明确标注。
  普通成员不能因进入首页获得公司全部数据；首页基础可见性与小聿可用性分别按现有门禁校验。
- 营收使用当前已发布达成口径；商机金额不计已确认营收，新客不能以客户建档数量冒充。
  指标缺数据／无权／计算中／失败分别呈现，不用HTML示例补位，不将未知写成0。
  统一周期、币种及单位，跨币种不直接相加；从指标进入分析携带口径、来源和时间。
- 机器人与气泡整体可点击，有悬停／聚焦反馈及减少动态适配；不侵占内容、不默认发声。
- 今日判断固定模板包括每日提要、摘要指标、重点判断、建议节奏、待验证事项。
  依据工作区业务日期主动形成每日汇报，记录范围和汇总时间；不是每访问一次重复调模型生成一份。
  来源更新／失效时重新核验，展示当前状态与历史汇总的差异。数字由业务规则计算，模型提供解释与建议。
- 每卡最多3个推荐动作，余项进入更多操作；同一判断重复进入优先续接原处理任务。
  讨论、暂缓、草稿已准备与业务已完成分别记录；正文不无限插入处理细节。

出口：首页数字可与原业务页对账；当前任务存在／无任务／已完成／无权限都能正确进入；相同业务日期的汇报稳定且处理状态刷新后保留。

### XC-03 动态任务协作空间

- 任务身份组件组由真实任务元数据提供；类型／名称／状态同组12px，常驻56px标题。历史对话按需进入，不加常驻第三栏。
- 定义有版本的成果契约与白名单组件：概述、来源、分析卡、计划／时间线、清单、表单差异、批准与逐项回执。
  内容和顺序按任务组装，不让模型输出任意可执行HTML，也不把一张客户表作为全部任务的模板。
- 首批类型：市场研判、业务表单准备与执行、今日判断衍生的跟进／分析任务；长内容摘要收敛，完整内容按需查看。
- 已有细分市场、方案、战略、公司销售规划四类表单可在任务区复核、补充并提交支持的动作；打开业务页为精修入口，非强制步骤。
  复用原字段配置、必填、字数、单位、成员UUID、关联、版本与发布校验；草稿不是新业务事实。
- 原任务续接、并行准备其他任务、回到历史任务各自保留草稿与输入；不得复制旧授权或静默合并私人对话。
- 空任务给出自然沟通入口；失败、部分完成、暂停、取消、过期授权、结果待核对都有明确下一步。

出口：同一真实研究可生成有来源的市场草稿；同一既有表单可在任务区和原页来回精修，人工改动不被覆盖，批准绑定所见版本。

### XC-04 客户批量登记闭环

- 把客户真实字段契约接入任务系统；现有客户查询与旧登记助手不等于已完成此项。
- 以10份可追溯的测试材料为固定样本：优先使用隔离测试数据；真实环境只在明确的测试数据范围内操作。识别现有客户／重复候选，核对名称、分类、区域、负责人及真实必填；不虚构联系信息。
- 公共字段可批量设置；人工单项修改优先；进入批量复核前重读来源和校验全部对象。
- 一次批准可覆盖同类、同范围、同版本的登记集合；保存走原客户服务，业务记录与执行回执按现有原子性约束落实。
- 部分失败逐项呈现，只重试失败／未执行项；结果未知先查回执，重复请求不能重复建档。
- 提交后提供每条客户UUID、版本与详情入口；登记不计为销售达成，也不顺带创建商机或发送消息。

出口：真实10条样本、重复候选、人工修改、权限变化、响应丢失、部分失败、撤销和重试均有核对证据。
结构上如需多对象草稿／批次关联，先评估复用现有对象；确需新增时使用增量DDL、Prisma与列锁同步，不先承诺“无数据库变更”。

### XC-05 全站页面与旧能力迁移

这一批按波次完成，但不因每个板块单独发布；每页的页面理解、读取、草稿、回填、保存、发布分别标记。

| 波次 | 模块 | 交付重点 |
|---|---|---|
| A | 战略、细分市场、产品目录、解决方案 | 与编辑区块对应的完整上下文；四模块既有能力接入同一对话；产品只开放已验收动作 |
| B | 销售规划、重点客户、承诺达成、赢丢复盘 | 公司／区域版本、指标口径、角色覆盖、达成与复盘依据；业务归属按36部署规格 |
| C | 客户、联系人、跟进、商机、报价 | 对象及关系、筛选／选中范围、页面补齐、旧提案与现有助手能力迁入；客户写入依XC-04 |
| D | 市场活动、信号、线索、漏斗、交付、回款、续约、功能域集合 | 迁移现有查询／分析／操作，不额外承诺尚无业务服务的自动写入；原页面动作不失效 |
| E | 配置、兼容入口、个人记忆、独立大屏、诊断与门禁 | 配置读权限与管理写权限分别处理，导航不改成面板；专用框架保留，只共享适用能力 |

- 已有助手方法逐一列出原入口、原调用、权限、新任务工具、回执与原入口迁移状态；不能只换名字丢掉原能力。
- 无对应工具的页面显示实际能力，不提供会假成功的按钮；原可用方法不能无说明退化为只读对话。
- 每个新增写动作必须复用原表单契约和域服务，并通过授权／版本／幂等验收；没完成不能借统一壳开放。
- 首批四表单之外的动作在迁移台账注明已登记、待验收或有具体依赖。上游缺能力走Runos补齐；真实依赖缺口列出，不吞进“全平台已接入”。

出口：逐页清单每项有新面板与上下文验收或明确的兼容／独立框架结果；旧助手能力没有未登记遗漏。

### XC-06 附件、技能、语音与导出

- “+”承载附件等材料入口；文件选择、上传、解析、可用于分析、失败分别有真实状态。处理能力优先复用Runos已授权能力。
  附件、解析文本、摘要与任务同本人／工作区边界；大小／类型／来源／保留规则采用配置；不自动变成团队知识。
- Skill默认自动调度，人工可选择合法能力；选择不等于执行或授权，目录分页、版本与依赖沿用现有Runos契约。
- 麦克风在发送旁，真实转写先进入可编辑输入，不自动发送。需使用已获授且适用的语音能力，拒绝授权／浏览器不支持时明确反馈，不用静态文字冒充。
- Enter发送、Shift+Enter换行、输入法组合输入、拖放和附件移除一并验证。
- 更多操作只保留一项“导出本次协作”，统一包含选定任务的成果和本轮对话，并说明导出范围；执行前复核本人、工作区和来源权限。
  不分出客户难以区分的下载成果／下载对话两套按钮。不在本轮新增团队知识维护或自动存为共享Skill。

出口：至少一份真实材料从上传到分析来源可核对；真实Skill调用与语音转写有可验证结果，失败和不可用状态不虚报；导出不泄露已撤权内容。
