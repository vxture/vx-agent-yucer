## AT-01：业务口径与完整交互方案

### 任务范围

- 明确八类页面模板：公司达成（合并总览）、客户达成、区域对比、单一区域、团队达成、我的达成、销售预测、预测记录。
  具体区域由授权清单生成，N个区域复用一个页面模板，不做N套页面布局。
- 为每页确定业务问题、概要、事实对照、解释／支撑、就近操作和下一步入口；移除无价值说明和重复数据。
- 制作足量可滚动、可切页的HTML；包含DS导航展开／图标轨、主内容柔性缩放、按需右侧小聿、
  窄宽面板、表格／卡片／图表的阅读层级。复用DS token、正文配置和既有标题高度／安全区规则。
- 给出四类目标的口径表：来源、目标、实际、周期、去重／归属、状态和详情去向。
  初步审计营收、新客、商机储备、毛利的数据可得性，写清存量与期间新增的区别。
- 设计正常、有差距、零目标、未设目标、来源未接入、数据待补、读取失败、权限不足、未归属及历史模式；
  HTML的模拟数据仅证明交互，不当作真实数据接入证据。

### 达成效果与检查

- 用户能从公司达成找到具体差距，进入公司重点经营或某区域看到客户／商机支撑，再看到处理入口。
- 展开与收起导航时信息结构不变；顶部期间／版本连续，小聿不丢当前任务；无效范围在原型中有明确状态。
- 一页只承担一个分析范围，不通过锚点或隐藏整块DOM把超长页伪装成多页。
- 交付HTML入口、关键状态截图、八类页面清单和口径／来源差额表，供用户整体检查后确认。

## AT-02：统一达成数据底座

### 任务范围

- 页面和智能体共用受控BFF／领域服务，智能体不能直连数据库；总览、各详细页及小聿复用同一授权口径。
- 接入有效发布目标及历史版本，核对公司／区域／团队／个人的期间、归属、币种及权限；
  不推算未设置的个人配额，不将公司与区域或年度与季度相加。
- 按AT-01确认的口径对照四类目标。当前成交的来源为已赢单商机金额，不能称为财务确认营收或回款；
  新客去重沿已登记对象身份，商机储备明确存量／新增／预计成交期间；
  毛利缺少可信成本或其他指标缺来源时显示待接入及原因，不伪造实际、完成率和风险。
- 分开达成状态与未来风险；依据已发布季度／节点目标判断进展，不机械按全年天数平均，
  不把期中低于年度保底直接判为落后；过期和证据不足商机不能只靠覆盖倍数包装成充足支撑。
- 隔离缺金额、缺日期、币种冲突和来源失败，保留可核实的指标并说明不完整性；
  未归属业务单列核对，不对零目标生成虚假超额／无穷大百分比。
- 分页按当前内容读取、复用授权汇总；如需要缓存，绑定租户／空间／权限／范围／版本，
  撤权后复核或失效，不能靠浏览器隐藏全量数据，也不能复用失效的摘要和检索结果。

### 达成效果与检查

- 同一范围的总览与详情金额一致；公司与区域差额能由未归属、统计范围或权限差异解释。
- 每个关键指标有来源、期间、口径和业务记录入口；缺失、真实零值、无权限和读取失败清楚区分。
- 单笔储备异常不抹掉已核实成交；目标修订和当前业务变化不改写历史报送基线。
- 定向核对聚合、版本、归属、边界及权限，交付来源对照和可复核样本；需要DDL时先说明迁移与兼容影响，
  不在本批执行生产迁移。

## AT-03：分页面分析工作区

### 任务范围

- 按确认预览接入DS导航和真实独立路由；公司达成、重点经营、大区对比／详情、团队／个人完成页面职责。
  同时接通预测和历史目的地；其业务增强在AT-04完成。
- 保留年度、兼容目标版本、期间与有效筛选，范围由目的地明确；深链、刷新、前进后退及旧入口正常。
  指定无效历史／范围不静默换成当前，页面状态和未保存草稿分别保护。
- 每页形成“结论 → 事实对照 → 差距解释 → 业务支撑 → 就近操作”；
  公司达成不展开完整客户商机推进清单，重点经营不重复公司四卡；大区对比不展开每区四季度，
  区域详情不再嵌入完整公司卡片。
- 将重点客户、商机、周期目标及数据待补项连到正确业务记录，带齐年度／版本／区域／期间。
  查看依据直接到合适详情或标准抽屉，不继续套多层展开。
- 严格对齐DS字号、图标、文字缩进、金额与单位、按钮层级、tooltip和内容安全区；
  页面不展示UUID，名称解析失败显示可理解的缺项状态。

### 达成效果与检查

- 用户可从公司达成的一条关注项进入公司重点经营的对应业务或本区详情；返回时条件保留。
- 长内容下导航／小聿开关柔性过渡，缩放、个人文字配置和窄屏不破坏阅读。
- 有权限才展示相应页面与操作，直接访问同样校验；导航隐藏不等于服务端授权。
- 完成八类页面入口及实际范围清单，提供完整路径截图和必要的交互／路由验证，不逐样式跑全量测试。

## AT-04：预测、历史与小聿协作闭环

### 任务范围

- 预测检视集中显示具体范围、预测依据、证据缺口、分类分歧和负责人判断，
  保留人工决定，不将规则或模型判断直接覆盖人的预测。
- 提交预测明确期间、范围、币种及目标依据，沿用不可变快照与原动作权限；
  大区对比／团队集合不能作为合成范围提交；公司达成／重点经营进入预测时明确采用公司范围。
- 历史回看显示选中快照及当时目标，明确当前与历史、两次历史之间的比较对象；
  期中兑现与期末准确率区分，不能拿当前目标和事实冒充当时记录。
- 业务问题可带范围、版本、记录及证据唤起共用小聿；导航只更新页面上下文，
  不自动发送、切任务或覆盖手动焦点和未发送输入。
- 从分析进入原业务表单复核，经用户确认后由受控动作执行，再回查／更新对应分析；
  保留来源、幂等、防重复、并发冲突及权限撤销处理，代理不能绕过服务或人类决策。
- 右侧权限、订阅、来源／模型暂不可用时保留授权事实与人工路径，明确哪些建议无法生成。

### 达成效果与检查

- 跑通一条完整链路：发现差距 → 查看依据 → 与小聿讨论 → 准备补充或修改 → 确认执行 → 回查结果。
- 另一条历史链路可核对“当时报了什么、后来变了什么”，不会因新目标发布而改变旧分母。
- 写入、只读拒绝、重复执行、失效权限和任务续接分别验证；不以打开面板代替能力验收。
- 交付流程证据、动作回执和仍待接入的能力清单；真实写入只在明确测试对象／范围中实施，
  不为验收随意修改正式预测或业务记录。
