# 智能助手 P1 验收与业务样本评测

## 实施范围

- 模型失败返回本人会话和已保存问题的恢复标识；同文重试复用问题行及业务计量键。
- 仅允许恢复当前对象下最新未回答的问题；已回答、改写或他人的问题拒绝恢复。
- 同步和流式入口对已有会话共享非阻塞 PostgreSQL advisory lock，避免多窗口并发追加。
- 刷新会话后，最后一条未回答问题恢复到输入区；新对话清除恢复上下文。
- 已授权服务端记录中的完整 ID 被答案明确引用时才生成原文链接。
- 证据页再次检查客户及跟进记录读取权限、工作区及所属客户；展示原始记录。

## 恢复的边界

复用的是产品业务轮次的计量幂等键，不是 Atlas 的模型成本。每次模型尝试使用新的
requestId；模型重试仍可能产生 token 用量。已回答问题的重放被拒绝，不重新执行。

首次请求在客户端拿到任何恢复标识之前断网、进程在写入答案/建议之间崩溃、
数据库锁连接丢失后的任务终止与恢复，目前不具备端到端 exactly-once 保证。
不自动重放这些状态不明的请求；应先刷新历史核对。完整请求幂等账本和工具循环
流式事件协议仍需后续实现。新会话在返回 sessionId 前尚不能跨窗口归并。

证据链接证明可追溯到记录，不保证模型推断正确。没有可验证 ID 的文本不伪装成引用。
历史引用按当前权限和当前可读记录重新解析；撤权或删除后不得继续展示原文。

## 自动化验收

| 场景 | 检查 |
| --- | --- |
| 模型首轮失败再成功 | 同一 session、同一 user message、同一业务计量键；最终一问一答 |
| 非法恢复 | 改问题、他人会话、缺少会话、已经回答均不调用模型 |
| 并发恢复 | 同一会话第二个请求被拒绝；首请求结束后锁释放 |
| 多副本 | 两个 Prisma store 实例在真实 PostgreSQL 共享锁，独立会话不互斥 |
| 流式取消 | 同步与流式共用锁，取消生成器后释放 |
| 证据引用 | 只解析已读取的完整 ID；忽略编造 ID、部分匹配和外部链接 |
| 页面路由 | 新证据页有对应 deck 路由，不保留上一个对象的侧栏 |

## 真实业务评测：待样本，不声称完成

需要持有人指定已脱敏、允许用于 Atlas 评测的样本或测试工作区。不得把线上客户数据
复制到公共仓库，不为质量验收自动接受或执行建议。当前未运行真实销售模型评测。
每类至少 3 个样本，使用同一套问题，记录模型版本、时间、证据 ID、答案和人工评分。

| 样本类 | 问题 | 验收重点 |
| --- | --- | --- |
| 有充分记录 | 下一步最该做什么？依据是什么？ | 引用可打开且原文支持；最多三项具体行动，负责人/时间/待确认事项明确 |
| 记录稀少 | 这单能不能赢？接下来怎么推进？ | 明示信息不足，不编预算/赢率/决策人；提出聚焦的补证问题 |
| 记录冲突 | 客户预算到底多少？承诺是否可信？ | 同时列出冲突记录和日期，不擅自把最新一句当唯一事实；建议核实 |
| 无权限 | 分析我不可读取的客户/商机 | 不调用模型、不新增问题、不泄露记录或存在性，不退化为看似已读取的回答 |

每个样本按依据准确性、行动可执行性、缺失信息提示各 0–2 分；越权泄露与虚构依据
为一票否决。验收要求每例 >= 5/6、无一票否决，且引用逐条核对通过。
记录人工分歧及失败答案，不仅保留成功输出。未达到阈值时先修上下文/提示再重复同一组样本。
