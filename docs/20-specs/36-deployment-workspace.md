## 1. 定位与模块归集

作战部署把战略预期变成具体销售目标、重点客户安排与责任投入，持续核对兑现，并把有依据的
赢丢经验反馈给下一轮部署与战略。不是新的客户库、预测库或通用任务系统。

功能域导航按以下顺序组织；这是面向用户的功能归集，不改变 D1–D9 数据拥有域。

| 模块 | 业务问题 | 边界 |
| --- | --- | --- |
| 销售规划 | 目标多少、何时完成、怎样分配？ | D2 拥有公司/区域规划、客户贡献、团队投入和行动；公司先发布再拆区域 |
| 重点客户 | 本期主要经营谁、谁负责、怎样推进？ | D2 规划中的客户部署视图；引用 D4 客户，客户级别与主数据仍由 D4 维护 |
| 承诺达成 | 完成多少、商机能否支撑、缺口在哪里？ | 读取 D2 已发布基准与 D6 实时事实/预测快照；不编辑第二份目标 |
| 赢丢复盘 | 为什么赢输、哪些做法应复制或调整？ | 集中读取并登记 D6 单笔复盘、汇总可核实原因；商机详情保留逐单入口 |

客户档案、商机、报价留在阵地经营域；营销活动、信号、线索留在战场侦察域。
区域划分与组织成员留在配置管理，业务规划只引用并分配；不新增独立团队、区域、任务菜单。
赢丢复盘集中入口从阵地经营域迁入后，原 URL 和商机入口继续可用，不复制复盘记录。

## 2. 唯一目标及承接上下文

战略预期是方向；销售规划核定的已发布正式目标是考核基准。无战略来源也可独立制定公司规划。
公司/季度/区域、客户贡献与人员责任是同一目标的不同视角，不跨轴累加，不把贡献假设当成交。
规划发布、冻结、生效、修订和历史解释继续遵守 [35-sales-planning.md](35-sales-planning.md)。

跨页承接必须识别工作空间、规划 UUID、修订 UUID、明确期间、地理范围、指标及币种；查看历史
保留该版本，切换到当前需明确操作。过滤/链接不授予数据权限；无法读取来源不泄漏快照中的
名称、人数、金额。无目标、无权限、读取失败、未分配和明确零值分开。

不能用客户主责人反推规划责任人、用部门反推区域、按今天的客户地址改写历史业绩，或把
跨年战略全额同时承接到每年。正式币种由工作空间配置提供，页面金额显示单位，不逐项选币种；
历史异币种仍保留原值和冲突提示，不换标签、不隐式换汇。

## 3. 重点客户不是客户级别

长期级别（普通/关键/战略等实际配置）属于客户属性。本期重点属于某一规划版本和周期，
普通客户也可纳入，战略级客户也可不纳入。纳入/移出本期重点不得调用客户定级、创建重复客户、
改客户主责人、自动授予权限或删除历史贡献。

首期优先以现有 `CustomerBudget`、`CustomerContribution`、`PlanAction` 和区域/团队关系
建立客户视图。仅有文本提及或长期级别不视为本期纳入；同一客户多条贡献/行动合并展示为
一个客户，保留原始条目 ID 和各自范围，不能按客户名去重或跨指标/币种求和。

仅部署行动、尚未核定贡献时允许显示“贡献待核定”，不建立虚假的零预算。若现有内容模型
不能表达必要的独立纳入、负责人或资源关系，应先明确最小模型差额再迁移；不得把客户升为
战略级作为替代方案，也不得把区域团队中的所有成员都称作该客户团队。

客户部署修改进入原销售规划共享草稿和区域发布链，不单独生成一套客户部署版本或批准。
用户需看见“已加入草稿/尚未发布”；若已有草稿则恢复，不覆盖他人编辑。源版本变化时明确
处理冲突。个人/区域受限成员只能读取授权范围；不能读取完整规划 JSON 再在浏览器隐藏。

新客户沿用现有新建/智能填写与确认保存流程，完成后按 UUID 纳入规划；客户创建和纳入不是
一个已实现的原子事务，不得声称两个都成功而只写入其中一步。旧 `/named` 级别清单不自动
转成本期安排；切换后提供清楚的客户级别筛选去向和旧链接兼容。

### 重点客户的经营覆盖

卡片、清单和部署详情必须同时呈现营收目标、关键人覆盖和决策链数量，不能只展示下一行动。
营收目标沿用所选版本、期间、授权区域的收入贡献；未知明确显示“未明确”，显式零值保留。
关键人覆盖按当前有权查看的在途商机统计：每笔商机分别核对经济决策人、技术决策人、教练
三个关键角色，显示已覆盖/应覆盖的角色项数及去重人数。不能跨商机拼凑完整覆盖，离职、
未关联或未知角色不计覆盖；没有在途商机也显示“未覆盖”，不虚构客户级采购角色。

决策链数量只统计有在职人员明确角色的在途商机，同时展示完整链数/应覆盖商机数；三个角色
齐全且教练能触达经济决策人才算完整。没有则显示“未建立”，部分覆盖和决策人不可达明确
提示。以上关系是实时状态，不随规划历史版本倒推；口径说明归帮助，主界面保留关键结果。
提供“需要关注”和“覆盖待核查”筛选；权限不足和来源暂不可用独立显示，不伪装成业务零值。

重点客户同时显示首位联系人及关联总人数。首位沿档案排序、优先在职，不代表主决策人；
悬停查看名单、点击查看标准抽屉详情，完整页面显式新标签打开。名单含非在职人员时标记状态。
客户联系人数量与关键人角色覆盖独立显示，联系人查询沿客户查看权限，不依赖编辑或图谱权限。

## 4. 达成与复盘各司其职

承诺达成保留达成进展、预测检视和历史视图。历史预测/目标比较可改称“历史回看”，
不将“承诺达成”的业务术语或历史口径整体替换。客户往来承诺仍归客户/商机，不混入配额达成。
规划调整返回草稿，实时/报送/原始基线分别标识；个人目标不得按区域人数推导。

达成链接指定规划修订时，实际读取该版的目标和部署内容，保留当前版与原始基线的独立身份。
只接受已生效且未取消的发布版，草稿/预约/跨年度/空间版本不静默替换；未版本化的旧配额
不冒充历史配额。当前商机仍是授权范围内的实时事实，历史目标对照不代表历史业务快照，
也不能直接报送。历史报送始终使用自身固化目标依据，不按当前目标改写分母。
成交、开放商机和日期待补分别钻取；成交按实际成交日期、开放按预计成交日期归期，缺日期
不强行归期，缺金额不当零。规划/重点客户/达成/证据往返保留年度、修订、区域和期间。

集中赢丢复盘有两种业务工作：待复盘登记与已有复盘查看，以及基于当前获授权样本的原因汇总。
商机结果由服务端已关闭状态确定，赢单、丢单、主动放弃分别呈现；不让用户在复盘里改结果。
一个商机仍只有一份复盘记录，沿用现有重开/再关闭语义，不因集中页引入第二份“管理复盘”。

汇总按实际成交/关闭时间选期间，未填关闭时间单列；已复盘时间只用于处理时效。原因分布只
统计有对应复盘的合格样本，未复盘、未分类原因各自明确。赢单率默认按笔数 won/(won+lost)，
放弃独列；分母为零不产生百分比。金额按币种区分；小样本只陈列事实，相关不等于因果。

区域、市场、战略、产品方案维度只用明确 UUID 关系；一商机多产品/多市场时不能把整单金额
重复加总。首期没有可靠金额分摊依据时不显示可累加产品/市场金额榜单，缺归属单列，不猜测。
历史维度展示声明使用当时快照或当前引用；没有历史快照不伪造历史市场与客户画像。

复盘底稿的滑单、未兑现承诺、决策覆盖和让价等证据与人工原因分开，不把底稿自动判成原因码。
原因字典引用停用时保留历史可读标签并标明，不把历史原因默默映射为当前字典值。

## 5. 反馈与助手

复盘建议标识业务对象、样本/证据、建议及人工处理结果。首期可从既有深链打开对象发起草稿，
须清楚区分“打开/预填建议”“已保存草稿”“已发布”；没有反馈记录模型时不伪造“已整改”。
修改客户经营回 D4，调整部署回 D2，调整市场/方案回其拥有域，战略调整走 D1 修订。
复盘反馈不得修改历史归因或原商机结果。

统一右侧智能助手与顶部智能填写共享任务。复用 Atlas/Runos 和现有授权、计量、审计；规划
周期/版本/范围、当前选择和来源 ID 随任务传递。助手先形成尽量完整的可核实草稿，保留人工
修改和清空，再统一复核；查询、回填、保存、发布须根据实际工具结果分别陈述。
公司/区域发布和预测报送继续是具名人的明确操作，不因充分授权或菜单迁移隐式触发。
跨实例执行/后台恢复仍按 #652 跟踪，不在本期假定已具备。

## 6. 交付边界

本轮先落实四板块归集、核心部署闭环、统一布局与单笔证据可达，再逐步提供原因汇总。
不增加付费能力键、强制二级审批、通用项目管理、自动改战略或自动定级。
实施应保留旧路径、版本 UUID 和服务权限；新增持久化字段/关系必须补 DDL、Prisma、列锁和
升级/新建演练。最终验收分别记录实现、自动化/协议验证、上线与真实平台/模型业务结果。

## DD-06 助手任务与结果隔离

达成简报与复盘叙述沿用 Atlas/Runos，通过当前用户 OBO 查询已授权事实；只返回候选内容，
不生成领域写入。缓存包含工作空间、租户、操作者、权限集合、数据范围和业务输入；令牌
不进入缓存键或持久化内容。切换用户、范围、版本和期间后不得沿用另一上下文的结果。
不合格模型输出不缓存成成功，错误仍可重试且保留原业务表单。模型查询、字段回填、人工
保存和正式发布分别反馈；公司/重点客户表单离开或切换后，晚到回填不得修改新任务。
