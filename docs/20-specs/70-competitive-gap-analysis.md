# 对标同类产品的功能差距梳理

本文回答一个问题：把 yucer 现有能力摆到「通用 CRM + 销售智能助手」这个品类里，
和同类产品比，缺什么、缺多少、缺不缺得起。不覆盖定价、UI 细节、性能，只看
**功能覆盖**。

## 对标对象与方法

三类产品各取样本，避免只对标一类导致偏科：

| 类别 | 样本 | 覆盖的能力形状 |
|------|------|--------------|
| 通用 CRM（含国产） | Salesforce Sales Cloud、HubSpot Sales Hub、纷享销客、销售易 | 客户/联系人、商机、报价合同、审批流、报表、开放平台 |
| 销售情报/预测类 | Gong、Clari、探迹、爱番番 | 通话智能、赢单预测、竞争情报、外部信号 |
| Agent 原生销售工具 | Artisan、11x、Sybill | 智能体自动执行、多渠道触达、会议纪要转结构化 |

方法：逐个能力域，列「yucer 现状」（基于 `app/(app)`、`app/(screen)` 实际路由和
`app/domains/*` 实际存在的域）、「同类产品典型做法」、「差距等级」。差距等级只分
三档：**无**（覆盖了核心场景）、**部分**（骨架在，深度不够）、**缺失**（完全没有）。

对`10-product-definition.md` 明确列为**非目标**的能力（报价单/合同文本/发票、
营销自动化引擎、通用项目管理、自建身份体系），本文不计入差距——那是产品边界的
主动选择，不是遗漏。会在最后单独列出，避免被误读成待办。

## yucer 现状速览（按实际路由核对，非按文档）

```
D1 战略      /strategy /segment
D2 规划      /planning /attainment
D3 市场执行  /campaign
D4 客户管理  /account
D5 商机侦探  /signal /lead /capture
D6 商机管理  /pipeline /forecast /funnel /winloss /named
D7 项目落地  /delivery /collection /renewal
D8 智能助手  /copilot /(screen)/enablement
D9 产品目录  /catalog /pricebook /solution /quote
admin        /admin/{member,role,org,industry,customer-type/size/nature,audit}
```

九个能力分区全部有对应的实际页面和域服务，不是文档画的空气分区——这一点和很多
早期产品「文档九个域、代码三个域」的常见差距不同，yucer 目前没有这个差距。

## 分域对比

### 客户与联系人管理（D4）

| 维度 | yucer | 同类典型 | 差距 |
|------|-------|---------|------|
| 客户主数据、分类（行业/性质/规模/类型） | 有，且比多数国产 CRM 的分类维度更细 | 有 | 无 |
| 联系人 + 决策角色 + 关系图谱 | 有（`account_relation` 有向图） | Salesforce 靠第三方插件、HubSpot 无原生关系图 | 无，甚至领先 |
| 客户 360 视图（跨域信息聚合到一屏） | **已确认**（2026-09-22）：`/account/[id]` 聚合 7/9 分区（D1/D2/D5/D6/D7/D8/D9），缺 D3 战役归因和 D4 信号（后者依赖批次 5） | 几乎所有 CRM 的门面功能 | **非缺口**（D3/D4 属各自分区待建） |
| 组织架构/多层级客户（集团-子公司） | 无迹象 | 销售易、Salesforce 企业版都支持 | **缺失**（To B 大客户场景常见需求） |
| 名片识别/批量导入客户 | 无 | 几乎所有 CRM 标配 | **缺失** |

### 线索与商机（D5/D6）

| 维度 | yucer | 同类典型 | 差距 |
|------|-------|---------|------|
| 商机阶段机 + 预测快照 | 有，且预测不可覆盖只追加，比多数产品口径更严谨 | 有 | 无 |
| 商机漏斗、赢丢复盘 | 有（`/funnel` `/winloss`） | 有 | 无 |
| 信号驱动的商机发现（不等销售录入） | 有（`/signal` `/capture`），是 yucer 的差异化卖点 | Gong/探迹类似，通用 CRM 通常没有 | 无，是优势项 |
| 报价单/合同生成 | 无（`/quote` 页存在但读的是 D9 目录定价，不是合同文本） | 通用 CRM 标配 | 明确非目标，不计差距 |
| 竞争对手情报（谁在跟这单竞争、历史胜率） | `CAPABILITY_SPEC` 提到「竞争」参谋能力，但无独立竞争对手实体/数据库 | Gong、Klue 有专门竞争情报模块 | **部分**（能力键存在，数据模型未见对应表） |
| 多币种/多国税务 | 无迹象 | Salesforce、HubSpot 企业版支持 | **缺失**（仅国内单一工作区场景够用） |

### 市场执行与获客（D3）

| 维度 | yucer | 同类典型 | 差距 |
|------|-------|---------|------|
| 战役与执行项管理 | 有（`/campaign`） | 有 | 无 |
| 邮件群发/落地页/广告投放 | 无 | HubSpot Marketing Hub、纷享销客 | 明确非目标，不计差距 |
| 多渠道触达自动化（企微/短信/电话外呼） | 无 | Artisan、11x 的核心卖点之一 | **缺失**，但落在「营销自动化」非目标边界内，是否要跨界需产品裁定 |

### 项目交付与回款（D7）

| 维度 | yucer | 同类典型 | 差距 |
|------|-------|---------|------|
| 里程碑 + 回款计划 | 有（`/delivery` `/collection` `/renewal`） | 部分 CRM 有，多数靠外部 ERP | 无，甚至比通用 CRM 做得深 |
| 续约/流失预警 | 有 `/renewal` 页，是否含流失评分模型需核实 | Gainsight 类专门做，Salesforce 靠插件 | **部分**，需核实是否只是台账还是有预测 |
| 甘特图/资源排程 | 无 | Salesforce 项目插件、Asana 集成 | 明确非目标，不计差距 |

### 智能助手 / Agent（D8）—— yucer 的核心差异化区

| 维度 | yucer | 同类典型 | 差距 |
|------|-------|---------|------|
| 建议动作可审阅（accept/reject），全程留痕 | 有，且刚做了「谁改了配置」的安全审计和「赋能分析」看板 | 多数 Agent 原生产品默认自动执行，人工审阅是后加的 | 无，是治理优势 |
| 会话式问答（copilot.ask） | 有 | 有 | 无 |
| 自动执行（autopilot，企业档） | 有开关，仅 enterprise 层，默认关闭 | Artisan/11x 默认这样卖 | 无，节奏不同但不是缺失 |
| 会议/通话转结构化（会议纪要自动生成商机更新） | 无迹象——`agent_message` 看不出有语音/会议输入通道 | Gong、Sybill 的核心功能 | **缺失**，是当前最大的单点差距（详见下方优先级） |
| 邮件/日历集成读取上下文 | 无迹象 | 几乎所有 Agent 原生工具的最小接入面 | **缺失** |
| 剧本/话术库（playbook） | 有 | Gong 有类似「最佳实践对比」 | 无 |

### 产品目录与报价（D9）

| 维度 | yucer | 同类典型 | 差距 |
|------|-------|---------|------|
| 产品/方案/价目表 | 有 | 有 | 无 |
| CPQ（配置-报价-审批流） | 无——`/quote` 只读目录定价，无审批链 | Salesforce CPQ、销售易报价审批是标配 | **部分**（`catalog.price` 权限存在，但无多级折扣审批流） |

### 平台能力（跨域）

| 维度 | yucer | 同类典型 | 差距 |
|------|-------|---------|------|
| 角色权限、组织管理 | 有，且刚完善了行操作（查看/关联成员） | 有 | 无 |
| 配置变更审计（安全审计） | 刚建成 `/admin/audit` | Salesforce Setup Audit Trail 类似 | 无 |
| 数据导入/导出（CSV/Excel） | 无——`40-capability-matrix.md` 自己确认「代码里没有 csv/pdf 导出」 | 几乎所有 CRM 标配，是新客户上线的第一道门槛 | **缺失**，优先级高 |
| 开放 API / Webhook 给第三方集成 | 未见迹象（平台层 C1/C2/C3 是身份/计费/计量通道，不是业务数据开放接口） | Salesforce/HubSpot 生态都靠开放 API | **缺失** |
| 移动端 | 未见迹象（纯 Web） | 几乎所有同类都有 | **缺失**，是否需要视目标用户（一线销售）的实际使用场景 |
| 报表/BI 自定义（自助拖拽报表） | 无——现有大屏（`/national` `/enablement`）是预设看板，不是自助报表 | Salesforce Reports、HubSpot 自定义报表 | **部分**（有预设分析，无自助能力） |

## 差距优先级（仅排序，不含实施方案）

按「同类产品覆盖率高 + 对 yucer 目标用户（一线销售/销售负责人）影响大」排序：

1. **数据导入/导出缺失** —— 新客户从旧系统迁移的第一步就卡住，是采购决策的前置门槛，不是锦上添花。
2. **会议/通话转结构化缺失** —— 这是 D8 智能助手当前唯一明显弱于 Agent 原生同类的点，而 D8 恰恰是产品定位的核心差异化区。
3. **CPQ 审批流部分缺失** —— `catalog.price` 权限设计已经预留了「谁能动底价」的位置，补审批流是在已有骨架上补深度，成本低于从零做。
4. ~~**客户 360 聚合视图需核实**~~ —— 2026-09-22 核实：`/account/[id]` 已聚合 7/9 分区，非缺口。
5. **多渠道触达自动化** —— 优先级最低，且直接踩在「不做营销自动化平台」的非目标边界上，需要先做产品裁定而不是直接列入待办。

## 明确排除在差距之外（产品主动边界，见 `10-product-definition.md`）

- 报价单/合同文本管理、发票开具
- 邮件群发引擎、落地页搭建器、广告投放对接
- 通用项目管理（研发看板、工时系统、资源池排程）
- 自建身份体系
