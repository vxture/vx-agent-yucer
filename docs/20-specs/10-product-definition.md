# 产品定义 - yucer 企业销售超级智能体

## 一句话定义

yucer 是一个面向 B2B 企业销售组织的超级智能体：它把**市场战略、销售规划、市场
执行、客户管理、商机侦探、商机管理、项目落地**串成一条可追溯的链路，并由一个
贯穿全链路的**销售智能助手**在每个环节给出下一步动作。

## 它解决的问题

企业销售组织普遍存在的断层是：战略在 PPT 里，规划在 Excel 里，执行在微信里，
商机在 CRM 里，交付在项目管理工具里，复盘在没人看的文档里。链路一断，就出现三个
后果：

1. **战略无法落地** - 定了打哪个细分市场，但没人能回答「本季度有多少商机真的来自
   这个细分市场」。
2. **预测不可信** - 商机阶段靠销售自报，预测靠拍脑袋，管理层拿不到可信的数字。
3. **经验不沉淀** - 赢单丢单的原因散落在个人身上，新人从零开始。

yucer 的产品主张是：**让整条链路共享一套数据与一个智能体**。每一个商机都能回溯到
它来自哪个战役、哪个细分市场、哪条战略；每一次赢丢复盘都回流成智能体的下一次
建议。

## 目标用户

| 角色 | 主要诉求 | 主要使用域 |
|------|---------|-----------|
| 销售负责人 / CRO | 战略落地、预测可信、资源投向 | D1 D2 D6 |
| 市场负责人 | 战役产出可归因到商机与回款 | D3 D5 |
| 一线销售 | 少填表、多拿下一步动作 | D4 D6 D8 |
| 售前 / 方案 | 客户决策链与竞争态势 | D4 D6 |
| 交付 / 项目经理 | 中标后按里程碑交付并回款 | D7 |
| 销售运营 | 配额、区域、口径、数据质量 | D2 D6 |

## 核心价值主张

1. **全链路可追溯** - 战略 -> 规划 -> 战役 -> 信号 -> 线索 -> 商机 -> 项目 -> 回款，
   每一跳都有数据上的父子关系，归因不靠人工填写。
2. **商机侦探** - 不等销售录入，而是主动从多源信号中发现并评分潜在商机。
3. **人机协同而非人机替代** - 智能体产出的是**可审阅的建议动作**，默认需要人确认；
   自动执行是最高档位下的显式授权，且全程留痕。
4. **复盘回流** - 赢丢复盘是结构化数据，直接喂给评分与建议，形成闭环。

## 明确的非目标（不做什么）

划清边界比罗列功能重要。yucer **不做**以下事情：

- **不做通用 CRM 的全部** - 不做报价单/合同文本管理/发票开具，只做与商机推进和
  回款计划直接相关的最小集合。
- **不做平台已有的能力** - 身份认证、订阅与计费、用量计量属于 Vxture 平台
  （C1/C2/C3 通道）。产品只读消费权益，**绝不本地实现商业判断**。
- **不做营销自动化平台** - D3 市场执行管到「战役与执行项」，不做邮件群发引擎、
  落地页搭建器、广告投放对接。
- **不做通用项目管理工具** - D7 只覆盖「中标后交付到回款」这一段，不做研发看板、
  工时系统、资源池排程。
- **不自建身份体系** - `workspace_id` / `tenant_id` / `sub` 一律是平台下发的引用键，
  产品侧只存引用，不做四层身份模型的镜像。

## 数据边界的硬约束

- 每张业务根表都带 `workspace_id`，它是**唯一权威隔离键**，永不从上下文推断。
- 归因键（线索的来源信号/来源战役、商机的来源战役）在创建时确定后**不可改**，
  它是归因的事实记录，不是可编辑字段。
- 阶段流转、预测快照、助手消息一律**只追加不修改**；纠错是新增一条记录。

具体到列级的写入白名单见 `deploy/database/ddl/98_column_locks.sql`——不在白名单里的
列，服务角色写入会直接 permission denied。
