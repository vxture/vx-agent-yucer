# 区域销售规划与版本管理

状态：首期模型、版本服务与界面已实现，验证与部署状态见实施计划。2026-11-11。

依据：owner 确定地域与组织分开、以区域整合阶梯目标/客户/团队，并要求规划调整可管理版本。
D2 拥有规划；D4 拥有客户主数据及客户经营计划；D6 拥有商机、预测与实际业绩。
实现设计见 [区域规划模型](../30-design/design_yucer_210_regional-sales-planning.md)。

## 1. 规划对象与边界

一份销售规划对应一个工作区、一个明确周期，包含公司目标、参与规划的地理区域、区域目标、
时间分解、客户贡献、团队投入和行动安排。区域来源为「配置管理 → 区域设置」，不由部门推导。
一个部门可负责多个区域，一个区域可由多个部门共同负责；没有部门也可按区域规划。

首期以年度规划为主，内部可分季度、按需分月；公司、区域、个人是不同目标作用域。
公司目标与区域分解不得重复加总，区域目标与个人配额也不互相累加。独立个人目标继续保留。
同一周期别名（如 Y2026 / 2026）识别为同一个周期，比较以明确的起止边界为准。
自定义财年必须提供日历、时区及边界，不猜测季度；「全部」是查看方式，不是可发布周期。

D1 战略规划可作为来源引用，与本文件的 D2 销售规划是不同业务对象。规划引用客户或团队，
不复制其维护能力、不改变客户级别、部门成员或商机归属，也不授予被引用对象的数据权限。

## 2. 阶梯目标与分解

| 项目 | 规则 |
| --- | --- |
| 三档目标 | 保底 / 目标 / 挑战；正式目标必填，另外两档可缺省；已填写时满足保底 ≤ 目标 ≤ 挑战 |
| 考核基准 | 默认使用正式「目标」档；草稿不是正式考核基准，保底不等于预测承诺 |
| 数值 | 非负、有限；新客户数为整数；缺省不是零；金额精确到最小货币单位 |
| 币种 | 金额按币种独立管理、比较和分配，不隐式换汇；数量不带币种 |
| 主要指标 | 区域卡片默认以收入为主；新客、管道、毛利可作为辅助目标，继承各自真实口径 |
| 零目标 | 可明确设为零；比例显示不适用，不产生无穷大，也不自动当作 100% |

各指标显式声明空间/时间聚合方式。收入可按互斥归属、互不重叠时间分解；新客按工作区首次
赢单的客户去重，不能把各区域客户数直接相加当作实际新客。管道是有观察时点及预测分类的
金额，季度计划不自动相加为年度管道；其既有口径不悄悄改成所有开放商机。毛利没有成本
数据时可规划，实际达成仍显示数据不足。只有口径与观察时点均一致才允许比较。

允许先设公司目标，再分配区域、季度和客户贡献。草稿允许缺项；发布时每个纳入区域必须有
主要指标的正式目标，或明确声明本周期不纳入并填写原因。部分分配可以发布，但须明确记录
待分配余额和说明；分配超出上级目标时拒绝发布。保底、目标、挑战分别校验。
时间子周期必须落在父周期内且同层不重叠；仅对可加指标要求合计与父级关系一致。
缺少保底/挑战的子项会使该档分配状态为「未完成」，不能假设其为零后宣称已全部分解。

未分配、未纳入、无权限、读失败和明确为零是不同状态。公司、区域、季度、客户贡献是同一
目标的分配视角，汇总时必须指定一条分配轴，禁止把几层或几条轴合并求和。

## 3. 客户与团队支撑

客户清单按区域及当前客户级别检索，成员在草稿中选择本周期重点客户，引用现有客户经营
计划并填写本区域贡献。发布时保留引用来源及当时的客户名称、级别、经营计划值和分配值。
以后客户改名、降级或经营计划调整，会产生来源变化提示，不自动改写已发布规划。

客户贡献属于计划假设，不能替代真实商机或成交。客户经营目标不因被多个区域引用而变大：
同一客户、周期、指标、币种的贡献在整份规划中统一分配，各区域分配合计不得超出已确认的
客户贡献预算。客户总部地址不强行决定全国客户的经营分工；主责区域与协同区域分别记录，
只计分配的金额。只有现有客户经营计划中的同口径数值才能作为来源预算；不匹配时须补明
本周期预算及依据。普通/关键客户也可作为目标支撑，战略客户单独标识。

团队规划包含主责人与协同人、部门、销售/售前等业务职责、投入期间、计划投入量和资源缺口。
职责不等于系统权限。团队归属复用组织架构，周期投入保存在规划中；规划不直接改组织设置。
两个人跨五个区域仍是两名实际成员，人数按成员身份去重。人力需求与已落实人员分开显示，
同一成员跨区域、重叠周期的投入合并检查，超配给出明确提示与说明，不以部门数替代人数。

行动安排记录目标、责任人、期限及支撑对象；执行反馈引用已有跟进/承诺等证据。执行中的
反馈更新不改变规划版本，计划责任人、预算或期限调整则进入下一版；两者在界面上分开。
智能助手可提示目标缺口、客户集中风险和人员冲突，建议须有事实与来源，采用既有授权和
裁决机制。发布规划必须是具名人的明确业务操作，不由自动采纳建议隐式触发。

## 4. 版本边界与生命周期

版本覆盖整份销售规划：公司目标、所有区域、地域范围快照、三档指标、时间分解、客户贡献、
人员投入、行动安排和假设说明在同一个版本内。跨区域调拨一次发布，不能各区域分别切换
导致公司汇总混用版本。界面可以只编辑一个区域，发布对象仍是整份规划。

| 操作 | 行为 |
| --- | --- |
| 创建草稿 | 首版空白建立；后续从当前生效版本复制，也可基于历史版本发起恢复草稿 |
| 保存草稿 | 修改同一草稿并检查并发编辑标记；每次保存不生成一个业务版本 |
| 发布 | 完整校验后生成 V1、V2…；冻结整份内容、发布人、调整说明及来源版本 |
| 立即生效 | 发布成功时启用新版本，前版留在历史；生效时间由服务端确定 |
| 定时生效 | 冻结后在未来指定时间启用；生效前沿用旧版本，明确显示下一版本及时间 |
| 取消定时生效 | 生效前取消调度事件；冻结内容和已用版本号保留，不能改成另一份内容 |
| 撤销草稿 | 放弃本次编辑，当前生效规划不变；保留审计记录 |
| 恢复历史方案 | 复制历史内容到新草稿，经当前校验后发布为新版本；不把旧版重新标为最新版 |
| 周期结案 | 锁定已结案周期；保留版本与复盘，不通过修改旧记录修饰成绩 |

日常进入页面及刷新时默认浏览当前生效版本，不因存在草稿自动进入编辑。
「新建规划」「调整规划」显式进入草稿编辑；已有草稿通过「继续编辑」恢复。
「发布规划」先保存当前输入并校验成功，再确认发布整份规划；失败时保留输入与错误信息。
发布成功后结束编辑并返回当前生效版本的只读视图。可以保存草稿后返回浏览，草稿不替代
当前生效目标；历史版本也始终只读，恢复须生成新草稿及后续新版本。

草稿中客户贡献、团队投入、行动和目标条目可编辑或移除；抽屉取消不落入草稿，校验失败保留
输入。移出区域或删除年度辅助指标时，先说明并确认关联影响，清理悬空引用而不改发布快照。
季度补齐不重复创建或补入已锁定周期；没有已结束周期时禁用锁定。取消未来生效事件保留
正在编辑的草稿及未保存输入，不能把版本操作当作放弃编辑。

首期每份规划一个共享可编辑草稿，以乐观锁防止覆盖他人修改。业务版本号仅在成功发布时
分配，不重用取消的版本号。已经冻结的版本不再更新内容或删除；当前/待生效/已替代是由
发布与生效事件推导的展示状态，不通过反复修改历史版本的内容或状态实现。

发布 V2 起必须填写调整原因，系统生成前后差异：目标绝对值及比例、季度调拨、客户增减及
贡献变化、人员投入变化、地域范围和关键假设变化。旧值为零时差异比例不适用。
旧版本不能直接覆盖新版本；草稿的基线已改变时须显式解决冲突，不自动变基或静默合并。
默认允许同一有规划维护权限的人发布，不强加二次审批；今后若增加审批，审批须绑定具体
草稿内容和编辑标记，内容变化后原批准失效。

## 5. 生效、变更和历史解释

生效时间不得早于本次发布，禁止追溯改目标。首期同一规划最多保留一个待生效版本；
要调整其内容或时间，先取消原调度，再发布新版本，替换调度在同一事务完成。
生效判断按时间及取消事件解析，不依赖定时任务成功更新某个「当前版本」字段。

已结案的季度/月度目标、当时客户贡献和团队分配保持锁定。年度调整可修改当前开放与未来
子周期，不能更改已锁定部分；年度目标不得小于已锁定部分的同口径合计。若必须更正历史
错误，另记具名、更正原因和独立更正记录，保留原报表与原值，不回填旧版本。
年度结案关闭尚存草稿及未来调度，结案事务后不得再发布；结案事件本身保留。

区域设置改名、重新划分、部门重组或人员离职，都不自动改写已经生效的周期规划。
当前配置和已发布快照有差异时提示变更，维护者在新草稿中确认采用或调整。
规划客户贡献不作为实际业绩分配；真实金额仍按 D6 的明确地理归属及已有口径计算。
主责/协同展示、人员调动不隐式移动历史实际金额。归属无法唯一确定时显示未分配，禁止猜测。

规划界面同时提供「原始基线」「当前生效」「待生效」「草稿」；原始基线是第一个实际生效
版本，取消且从未生效的发布不算基线。当前可按现行目标重算本期进度，同时对照原始目标，
明确分母版本及观察时点。达成详情继续在承诺达成工作区，不复制一套成绩报表。

**历史复盘绑定当时实际采用的目标版本和预测快照。** 以后降低目标不能把过去的低达成率
改成高达成率；年度/季度、不同时点、不同地域边界或指标口径的数值也不得隐式混算。
新快照缺目标时明确记为无目标；已有无版本绑定的历史快照显示旧口径，不能伪造 V1。
查看历史仍按当前权限控制，不因内容已冻结而暴露已失去权限的客户或个人信息。

## 6. 一个调整示例

V1：公司年度目标 3,000 万；东部 1,000 万、南部 800 万、其他区域合计 1,200 万。
东部季度目标为 200 / 250 / 250 / 300 万，其中 Q1 已结案。

V2：东部调整至 1,100 万，南部调整至 700 万；公司目标仍为 3,000 万。
东部季度改为 200 / 250 / 300 / 350 万，Q1 不变，并同步调整客户贡献与售前投入。
发布说明为「跨区项目重分配，调整下半年目标与资源」。

发布前旧版持续生效；发布成功后一次切换公司和所有区域。Q1 历史复盘继续引用 V1；
年度现行视图采用 V2 并同时显示 V1 原始目标。V2 内容出错时复制并发布 V3 更正，不删除 V2。

## 7. 实施边界

本模型在现有 D2 能力内实施，不新增商业 feature key。已有权益、读写权限和记录范围仍然
适用；版本发布不会把规划权限扩大成客户管理、组织维护或预测提交权限。
保存/发布/取消调度/结案的规则同时由服务层及数据库兜底，历史版本不能只靠前端禁止修改。
数据库实施必须具备 DDL 增量、Prisma、角色授权、列锁镜像及真实 Postgres 契约测试。

## 10. 首期实现边界

本期界面提供自然年及四季度目标、区域卡片/清单、客户贡献、实际人员/需求岗位、行动安排、
完整版本差异、未来生效/取消、恢复新版本、季度锁定与年度结案。模型保留自然月表达能力，
界面暂不创建月度分解或自定义财年。个人配额沿用原入口，不参与公司/区域合计。

完整规划包含跨区域客户和成员快照，首期仅对工作区范围的规划操作者开放；受限范围用户
保留原目标视图，不能获取完整版本明细。含客户/团队的历史版本读取同样验证当前来源权限。
客户经营计划提供匹配周期预算参考，手动修改预算须记录依据，不直接修改客户经营目标。

规划检查为确定性规则，依据所选版本提示目标缺项、客户覆盖缺口、人员缺口、重叠超配及
客户集中度，并可定位区域。助手通用目标上下文使用统一生效目标；完整规划的模型建议、
执行证据自动关联与专门复盘对话仍是后续工作，未配置模型时不宣称完成模型业务评测。
旧历史保持旧口径；新预测提交将实际采用的目标版本与预测快照同事务冻结。
