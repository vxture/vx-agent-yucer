# 01 - 致平台线：karda 与 arda 的接入契约请求

- 时间戳：2608161131
- 发件：`vx-agent-yucer`（产品线）
- 收件：平台线（`vxture`）
- 状态：待回复
- 相关裁定：[ADR-007](../30-design/decisions/ADR-007-karda-as-the-only-knowledge-crossing.md)、
  [ADR-011](../30-design/decisions/ADR-011-arda-on-the-signal-seam.md)

## 缘起

owner 于 2026-08-16 指示 yucer 接入两个平台面：**karda**（所有 agent 都要链接的知识
平台，用于跨 agent 知识共享）与 **arda**（共享数据平台；产品可自建业务库，但需对接
arda 实现共享与数据获取）。

yucer 已按 `CLAUDE.md` 的规矩落了两条 ADR，把**属于产品自己的立场**定了下来
（不自建第二个知识存储；arda 作为入站事实来源接在信号缝上，一期零 DDL、只取数）。

**属于平台的部分，本仓一律不猜。** 下列问题就是那部分。

## 提问口径

**每一条的答案都会改代码。** 只会改文档的问题没有列进来。每条后面标了「改什么」。

一件已经发生的事，供参考：本仓在 2026-08-15 曾试写过一版 karda 客户端，含一个对外
披露边界模块。它已被整体丢弃——一次独立对抗审查在那个 137 行的边界文件里查出**四条
各自独立的客户名称越界路径**，根因是在受众模型、留存模型、撤回模型均未知的情况下去
规定一条不可逆的披露边界。**在 C 段与第 16 问回答之前，本仓不会重写它。**

## B. arda：卡住一期「能跑」，不卡「能合并」

一期代码可合并、可单测，但在 5 到 11 回答之前跑不起来。这与 Atlas / Runos 今天的
状态相同（base URL 未绑定）。

| # | 问题 | 答案会改什么 |
|---|------|------------|
| 5 | **各环境 base URL**（beta / prod）。像 Atlas 与 Runos 一样只在 tailnet 内，还是公网可达？ | `.env.example` 取值与部署配置 |
| 6 | **工作区身份**：arda 是按 yucer 已经在铸的那个平台 `workspace_id` 划界，还是自有一套租户键？ | `ArdaContext.workspaceId` 是否够用。**若需映射表，那就是 DDL，零 DDL 这条性质随之失效** |
| 7 | **水位语义**：是否有 since 查询？是否容忍**重叠**窗口？是否返回一个必须由**调用方**自持的续取游标？ | 决定「推导水位」这个设计能否成立，还是必须冒出一张本地游标表。**这一问单独决定 ADR-011「零 DDL」是否成立** |
| 8 | **记录标识**：是否有稳定、不可变、不透明的单记录 id？长度是否 ≤ 255 字符？ | `signal.source_ref` 是 `VARCHAR(255)`，且是判重键的一半。id 更长或不稳定，适配器就必须改为取哈希，判重语义随之改变 |
| 9 | **事实分类法**：arda 的类型词汇表是什么？是否封闭？是否带版本？ | 适配器的映射表；以及 `chk_signal_type` 现有七个取值是否需要按增量放宽 |
| 10 | **时间戳**：一条记录是否携带与「录入时刻」「返回时刻」不同的**「事实发生时刻」**？ | `signal.detected_at` 从哪个字段映射。**该列插入即冻结，选错只能靠 db-init 数据订正** |
| 11 | **未开通工作区的行为**：没有 arda 权益的工作区，收到 403 还是空列表？ | 作业账目能否区分「未开通」与「市场安静」。ADR-010 第 5 条存在的理由就是：一个分不清这两者的扫描，会让所有人都以为活干过了 |

## C. karda：卡住**任何**代码

在这一段全部回答之前，本仓不写一行 karda 代码。

| # | 问题 | 答案会改什么 |
|---|------|------------|
| 12 | **产品侧是否存在发布方向**，还是 karda 只是从策展库到产品的**只读分发**？ | 决定 yucer 是否需要建对外披露边界。**若 karda 只读，那个边界模块就不该以任何形式存在——这是本方案里最大的一个分叉** |
| 13 | **读者集合与受众模型**：一条知识谁能读——所有 vxture agent，还是受限子集？描述这个范围的词汇是什么？ | 决定 yucer 那版被丢弃代码里自造的 `workspace / tenant / platform` 三档是有意义还是根本就错 |
| 14 | **单条 provenance**：每条知识是否**一等公民地**携带断言方 agent、版本、断言时刻？ | 决定外部知识**能否被引用**。没有这三者，它进不了 ADR-004 围栏纪律下的接地路径，这个集成也就不值得建 |
| 15 | **单条内容摘要**：karda 是否像 Runos 对 Skill 那样提供内容摘要？ | 决定提示词围栏能否渲染 `verified` / `unverified`（即 `renderSkillPrompt` 那个形状），还是只能一律标 unverified |

- `ADR-007`：知识只经 karda；契约发布前**零代码**，且「没有」就是当前状态本身，不是待补的桩。
- `ADR-011`：arda 接在信号缝上；一期只取数、不外发、零 DDL，带 90 天杀死判据。
- arda 一期代码：端口返回 yucer **自有**的 `NewSignal` 类型，全仓唯一一处对线格式的
  猜测被隔离在 `platform/arda/http-source.ts` 一个文件里。
- 未配置即为空来源，且**那是正常状态**，不是故障——与 Runos 生产目录当前为空时
  `runos_discover` 返回空列表是正常返回，同一口径。
