## 2. 域与页面骨架

Launcher 及域内导航固定顺序：销售规划、重点客户、承诺达成、赢丢复盘。
域介绍建议“定目标、配客户、落责任、看兑现、复经验”，用户页面采用简短业务文案。
域级总览不设第五个 Launcher 模块；域名进入已有 `/domain/deployment`，展示跨板块待办和缺口。
阵地经营保留客户管理、商机管理、报价管理；商机页保留单笔复盘。

页面共同骨架（按现有战略装备域，而非复制旧设计文档的过时入口）：

```text
面包屑 / 域内导航
页面大标题                                  次操作  主操作  ⋮
统一上下文：期间 / 区域或我的范围 / 已发布版本（按任务需要）
icon 区块标题  ?  [卡片/清单]  数量             搜索  筛选  操作  ⋮
当前业务内容
历史内容（需要时默认折叠）
```

- 全局操作走 `ModuleHeadline`、`PageActionRow`、`PageActionButton`；区块工具行复用
  `CollectionToolbar`，表格复用 `CollectionTable`/现有排序选择包装，DS 元件与 token 为准。
- 标题区只放跨页主操作；区块操作作用于当前视图/选择；批量操作仅选择后显示。不为凑四字
  截断关键业务含义，常用按钮优先“新建规划、调整规划、保存草稿、发布公司、拆解区域、
  纳入客户、登记复盘、查看商机”，名称须与真实对象及动作相符。
- 筛选只保留当前任务所需：统一期间和授权范围；版本切换保留只读历史；不能把已选择的
  历史修订静默切成当前版。复盘跨年度只读统计可使用明确范围，无需强绑一份规划。
- 14px 常规内容；编辑 label 12px 淡色、content 14px 主色。只读 `icon + label：content`
  同行 14px，首行对齐，长文从内容列换行。沿用 16px 头像配 14px 名称的整体人员组件，
  不撑高行。数量淡化单位，金额取全局币种显示；未知不加虚假单位/百分比。
- 说明进入标题 `?` 帮助抽屉；字段 `?` tooltip 简短、宽度正常且不遮字段，采用 DS 定位。
  业务错误、未保存、版本过期与权限拒绝仍就地出现，不能全藏帮助。

## 3. 三类内容形态

统一外壳与密度，不把所有板块强做成战略大卡。

| 形态 | 使用处 | 布局 |
| --- | --- | --- |
| 总览卡片 | 公司规划/区域部署、域级任务 | 战略式较宽卡，身份/版本在上、关键目标与责任在中、支撑统计在下；最多一行主指标，不堆全文 |
| 引用卡片 | 重点客户、商机关联、反馈对象 | 适中高度，名称/状态、两三行关键业务信息、下一行动；更多进入详情或抽屉 |
| 证据/表格 | 达成比较、原因分布、历史和复盘明细 | 原生业务表/进度/时间线；原始金额、分母/样本、观察时点清楚，不用装饰卡片取代可比性 |

卡片“主指标”与引用计数区分，不把预期贡献、在手商机、实际成交混成同一个金额。
共享战略域 overview/detail/reference 三种间距 token；提取必要的中性业务语义薄封装，
不修改 DS 源码、复制 DS 或在各页自由调整 padding。当前战略专名包装不直接到处套用。

关联摘要两行裁剪，长名称单行/两行保留全称可达。点击 card 非交互区域打开标准详情抽屉；
标题 hover 变色无下划线，进入对象所属模块详情；按钮/链接阻止触发 card 打开，不套嵌 button。
独立业务对象用完整详情页，编辑与展示板块对应，不能用万能抽屉塞满所有引用内容。

## 4. 各板块具体页面

### 4.1 销售规划

不另造“所有规划清单”遮住现有年度工作区。期间/版本选择后默认当前生效只读视图，有草稿
展示“继续编辑”，不自动进入编辑。主卡显示周期、公司目标、版本、负责人及阶段。

业务顺序：公司目标 → 战略承接 → 区域部署 → 客户支撑 → 团队投入 → 行动安排。
公司先发布、区域再基于公司发布版本拆解；编辑公司时不混进区域编辑入口。未纳入/未分配
余额保留说明，不能把缺失展示成全部完成。保底/目标/挑战、季度自动填写与锁定规则沿用。

区域卡与清单表达同一数据；卡片重点突出目标、缺口、责任与客户/人员落实情况；表格便于
横向比较。点击标题到该区域部署详情，详情内再分客户、团队、行动同级板块。主页面不把
每个客户的整个档案展开。公司/区域编辑保存草稿，发布前检查分析与确认使用真实后台结果。

### 4.2 重点客户

默认当前周期已发布规划的客户部署集合，来源为贡献/预算/行动的并集并按客户 UUID 合并。
页面显示当前修订；查看草稿需显式切换，不把草稿安排当正式部署。无已发布规划时明确引导
建立公司规划或继续草稿，不回退到所有战略级客户冒充已部署。

卡片：名称、编号/长期级别；部署区域、客户主责、营收目标、关键人覆盖、决策链；底部关注提示和下一行动/负责人/期限。
长期级别只是客户引用，不作为纳入条件。不能推导出的人员/进展显示待落实，不能从
客户联系人或区域所有成员猜测。跨区域分别展开，不能把主责/协同金额重复相加。

清单首期列：客户名称（编号/级别作辅助）、区域、营收目标、关系覆盖（关键人/决策链）、下一行动（含行动负责人和期限）、
部署状态及操作。商机在详情按授权和所选期间展示，未建立商机贡献归因时不制造“支撑金额”。
金额只展示收入指标并标明，其他指标在详情独立，不混算；客户主责与行动责任分开。

“纳入客户”标准多选抽屉显示现有客户，普通/关键/战略均可选。选择后进入当前区域草稿，
可分步填写贡献或行动；金额未知留待核定，不逼填零值。“保存草稿”后提示尚未发布，
从“发布区域”沿既有版本链生效。若现模型不支持贡献尚未知的安排，用真实行动关系表达，
不足项提交最小模型评估，不在 UI 上伪造一项永久重点标记。

详情完整页按部署摘要、贡献安排、推进任务、团队支持、相关商机/证据组织；客户背景只保留
紧凑引用，通过“客户档案”打开客户全景，面包屑和返回清单保留年度/修订/期间/区域。客户主责人与本次部署负责人分别命名。
旧级别筛选入口保留向客户管理的明确去向，旧 URL 不做含义不明的跳转或静默数据迁移。

### 4.3 承诺达成

保留“达成进展 / 预测检视 / 历史回看”，以当前已有的范围、版本、实时及报送口径为基础。
达成进展优先进度表与区域卡；预测检视优先商机表，不强加 card/list 按钮；历史使用快照
表与时间序列。只在相同业务数据有两种有效布局时展示模式切换。

首屏保留正式目标、实际成交、达成率、缺口/超额四个简明摘要；其余统计汇入对应工具行，
不再一层层叠指标卡。重点客户、目标来源、支撑商机、战略兑现为同级业务板块。
点击缺口或商机额查看过滤后的证据，返回时保留版本/期间/区域；“调整规划”回原版本链，
“登记复盘”到已关闭商机，不能从未关闭商机自动生成赢丢结果。

### 4.4 赢丢复盘

两个内部视图：复盘清单、原因分析。清单含待复盘/全部的范围切换与赢单/丢单/放弃筛选；
不把“已复盘”默认为历史折叠区，当前周期已复盘结果本身就是主要内容。

卡片保持中等高度，客户/商机名称、结果金额/结束时间、主因/摘要及复盘状态即可；表格提供
名称、客户、结果、金额、关闭日期、主要原因、负责人/复盘人及操作，避免宽表一次塞满两个人名。
商机名称打开商机详情，card 非交互区域/查看复盘打开标准抽屉；证据多时进入已有商机复盘
上下文，不堆多层抽屉。待复盘状态与复盘记录是否存在、原因是否缺失分别判断，沿用服务规则。

登记表优先三列短项，原因来自工作空间字典；结果只读、原因不由模型预选。经验说明单独全宽，
先呈现可核实底稿，人工填写原因。修复 Promise 未等待、异常恢复和同步在途锁，失败保留输入，
重复点击不生成重复复盘；重新打开已有复盘不得把有记录错误说成未登记。

原因分析默认明确周期，显示样本、已复盘覆盖、赢/丢/放弃、原因分布和证据清单；未复盘/
未分类/未归属分别列示。指标按规格口径。没有可靠产品金额分摊时展示关联笔数与来源，
不做重复金额排行榜。后台必须按权限聚合并保留钻取条件，不能下载全库在浏览器统计。

反馈操作按建议对象命名（例如“调整规划”“查看方案”）；首期可靠深链和人工修订优先。
没有实际反馈持久化时，只标“待采纳建议”，不能虚构进度看板或自动发布。

## 5. 模式、历史、表格与侧栏

- 有效的 card/list 视图复用 `CollectionViewProvider` 和 `yucer_collection_view`，与战略域
  使用同一偏好。视图类型、筛选、当前修订分别管理；偏好不能把预测/时间线硬改成卡片。
- 历史仅指过往周期、被替代版本或明确归档业务；card 模式默认收起、list 模式展开；搜索
  只命中历史时自动揭示结果。版本快照表与重复客户引用不能混成“历史客户”。
- 清单沿用统一标题字号、排序按钮及表头高度；名称优先空间，数字右对齐且有单位、时间和
  人员固定合理宽度。必要列排序以原始值比较，未知稳定放末尾；翻页/切换不丢排序。
- 序号与选择复用现有合并列：常态序号，选择后显示选中态；行空白切选择、标题打开详情，
  操作按钮不切选择。键盘有显式选框、标题可聚焦；无批量操作的表不强加选择列。
- 抽屉使用现有 `collectionDrawerWidth.standard=md` / `wide=lg`，不自定像素。帮助、单对象
  预览、人员/市场/客户关联默认 md；确有密集比较任务再用 lg。移动端使用 DS 视口适配。
- 选择抽屉多选/确认/取消一次提交，取消不改草稿。日期范围一律 DS 双日历组合控件，底部
  翻月位置稳定；短项三列、描述全宽，必填与字数提示沿用业务限制，未知不填猜测数字。
- 编辑底部固定操作栏留安全区；有未保存修改离开确认。详情与编辑同级板块对应，编辑过程
  的“高级设置”仅是展开提示，详情有内容则正常显示，无内容不留空壳。

## 6. 域首页与统一助手

域首页按选定期间和获授权范围读取当前发布版：战略未承接、区域未分配、客户缺部署责任/
下一行动、商机支撑缺口、待复盘。每项有可信来源和去向；旧目标字段先核实，不能只换标签。
计划客户贡献≠已成交，缺事实≠确定未执行。无权查看总览时仅显示可访问模块，不能靠统计泄漏。

助手保持统一框架标题、授权模式、宽/窄/全屏。四板块各自注册任务上下文和可回填字段：
规划提出分解草稿；重点客户筛选并安排贡献/行动；达成解释证据与缺口；复盘整理底稿并提出
候选原因及改进建议。候选原因不覆盖人工选择，发布/提交仍明确确认。
切换对象/期间/修订后旧结果标失效或终止，失败保留表单和问题，可重试。上下文不跨空间复用。
顶部智能填写适用于表单；右侧负责多轮分析，两者同一会话草稿不互相覆盖，不另接模型。

## 7. 交互验收与预览

DD-00 是可审查设计，不制作能点但无数据约束的伪业务页。实施时用本地隔离数据预览
公司/区域/个人权限、0/未知/空状态、旧版与草稿、长名称/长文和人员缺失。
至少验证宽屏/单侧栏/双侧栏/移动宽度，主内容不横向溢出，表格自身可滚动。
共用外壳验证标题操作对齐、控件高度、同类行距/分隔线、DS 抽屉、双日历、焦点与键盘。
业务验收按同一规划 UUID/修订/周期贯穿四板块，不能只以截图或假模型回答证明完成。

## DD-02 销售规划落地补充（2026-11-20）

区域总览采用年度收入目标、同目标客户支撑、支撑缺口三个金额；客户/成员/行动数量归为
部署安排，负责人紧邻区域名称，金额单位与数值一起显示。无明确年度贡献时显示缺值，
不把四季贡献相加补成年预算。明细入口携带年度、修订、区域和期间。

公司与区域编辑沿用同一年度共享草稿。智能填写首期作用于当前编辑范围的年度目标和前提，
由现有表单规则自动生成阶梯与季度；不生成第二份规划、不保存或发布。会话绑定草稿令牌，
模型前后核对生效基准和草稿令牌；请求期间的人工变化不被旧回答覆盖。客户/团队/行动等
后续任务继续在相应批次扩充同一链路。

## 8. DD-03 最小模型与保存约定

- 使用规划既有 `budgets`、`contributions`、`actions`，无独立“重点”标记或客户专属团队字段。
  普通客户可通过真实行动先纳入；未知贡献留空，不建立假零预算；长期级别不自动升级。
- 所有写入进入同一地区规划草稿。UUID、编辑令牌、事件序号、幂等请求共同校验，来源和
  锁定期间由原规划服务复核。移出限定所选期间及区域，年度包含子周期，保留其他区域/期间。
- 清单和详情先在服务端按 workspace/territory/unit/own 投影；个人只看明确分配给自己的
  行动及相应区域贡献，不泄漏其他区域、整客预算、规划前提、全区域目标或行动证据。
  无成员目录权限不展示他人身份；无完整来源权限不提供整版编辑入口。
- 标准 md 抽屉承载多选、行动、贡献与移出；刷新候选不重挂编辑器、不丢当前输入。
  客户新建单独保存，返回后刷新纳入；不会宣称创建与纳入是同一原子操作。
- 智能填写复用 Atlas/Runos 的 OBO、会话、审计和计量，只返回当前行动/贡献字段；会话绑定
  操作者、工作空间、客户 UUID、区域、目标、草稿 UUID 和编辑令牌。保存前人复核，发布回销售规划。
- 区域支持明确标记为公共团队，不把区域投入直接当作某客户专属投入；相关商机是当前授权
  实时记录，按所选期间的预计成交/关闭日期筛选，不冒充历史归因快照。

## 9. DD-03 经营覆盖补充

- 复用 account 的 `REQUIRED_ROLES`、`chainForOpportunity`、`analyzeChain`，按商机核对
  三个必要角色与教练到经济决策人的可达性；同一客户多商机累计角色位、去重计人数。
  空商机不计已建立链，不混用联系人总数或商机总数。
- 服务端先完成规划及客户范围投影，再读取 session-scoped pipeline；同时要求
  `account.graph.view` 与 `pipeline.view`。只对可见客户的在途商机批读一次角色关联，
  每轮最多并行六个客户的联系人/关系读取；仅返回统计数，不下发联系人或隐藏商机身份。
- 关键人和决策链是客户实时关系，所选周期只决定营收目标与部署条目，不把实时关系冒充
  历史快照。某客户关系失败不影响其他客户；全局来源失败与权限不足独立表达。
- 卡片、表格和详情复用相同的数字/缺口组件；已知缺口使用警示语气，额外提供关注筛选。
  三项经营指标缺失时直接说未明确、未覆盖、未建立；说明放工具行及详情帮助。

## 10. DD-03 联系人摘要与详情

联系人姓名与总数是紧凑引用，关键人覆盖另行保留，避免联系人数量冒充采购角色覆盖。
`contactSummaries` 优先在职并保留组内档案排序，总数为全部关联人数；离职/作废人员在名单
显示状态。服务端按客户范围读取，供规划覆盖使用的原始缓存只在请求内存在，客户端只接收
首位身份与总数。悬停/键盘聚焦用 DS HoverCard 按需获取只读名单；点击触发标准 md Drawer，
详情中的完整页面链接显式在新标签打开。抽屉与完整页共用 `ContactDetails`，无第二套表单。

所有详情请求使用客户 UUID + 联系人 UUID，复用 `getAccountDetail` 客户查看门禁及 scoped store，
不依赖编辑权限或决策链高级能力。联系人不属于该客户或当前范围均不返回。独立页保留客户
面包屑、档案入口，并按原编辑权限显示编辑资料；编辑返回联系人页，非用户输入的任意外链。

## 11. DD-04 达成依据与证据

达成区把筛选与目标依据集中于紧凑上下文行。当前视图以标题标签表示，其他可达视图进入
标题右侧三竖点菜单；报送仍为直接主操作，详细层级见第13节。
当前目标可正常报送；选取历史目标仅做实时对照，目标版本列表只含已生效、未取消的发布，
当前发布与原始基线分别展示。无有效版本直接提示，不一边显示旧版名一边使用当前分母。

读取旧版时保留选中快照的地域边界、目标与支撑；当前商机仍按其实际地域/成交日期读取，
明确不能当成当时的业务快照。区域投影仍先受 scope 约束，个人配额不由公司版推算。
历史报送继续使用自身固定 targetBasis，不用当前目标重算报送达成率。

成交数字进入成交明细、储备进入开放商机；日期待补独列且不归入周期加总。证据表采用共享
CollectionTable、标题字号、排序/列宽；来自同一授权商机集合，与页面金额保持同口径。
规划、重点客户与达成往返携带 revision/period/region，同年季度切换保留版本，年度和个人
视角切换清掉不适用版本。模型简报沿现有能力调用，明确所选目标与实时数字，不进行写入。

## 12. DD-05 复盘清单与原因分析

聚合读先按现有 session-scoped 商机读取授权关闭样本，再批量读取这些 UUID 的复盘；不先向
浏览器下发全库后筛选。单条复盘读取同样验证可见商机，待复盘限额在权限投影后应用。
清单含已复盘样本，不能以“已登记”禁用查看；编辑仍由原 recordWinLossReview 保存同一条记录。

原因分布要求已登记、原因非空且复盘结果等于当前关闭结果；不一致单列待核，点击原因的清单
使用完全相同口径。原因引用不可用在内部保留 ID，页面显示不可用标识，不展示 UUID。字典没有停用字段，不伪造该状态。
未复盘、未分类、结果变化分别计数；日期待补不进入周期数，录入日期仅作处理时效。
金额使用当前商机金额，按币种分别汇总，未知单列；客户/战略/市场行动为当前引用而非历史快照。

标准 md 抽屉承载查看/登记/修改，商机详情链接保留完整底稿入口；相关对象操作只打开所属模块，
不虚构反馈进度。两处登记复用同一组件、服务与失败恢复；模型叙述沿已有服务，来源不可用不可
解释为事实缺失或负面结果，建议原因仅由人显式采纳。

## DD-06 助手链路收尾

达成简报和复盘叙述共用既有 `runAdvisor` → `runCopilotTurn` 链路，补齐当前会话 OBO，
与规划、重点客户保持相同授权来源。只读分析允许 Runos 查询而不产生提案或领域写入，
复盘候选原因继续由人明确采纳。缓存按用户、权限、范围及业务上下文隔离，保持原有
advisor 计量与 Atlas/Runos 任务关联；未通过内容准入的答复不保存为缓存成功。

表单共享助手以页面/对象/版本的 React key 为任务边界。卸载会使该次回调失效，并释放
父表单 busy 状态；旧请求最终完成时不能回填、追加对话或清除新任务的 busy。
重点客户切换期间、区域、客户和草稿令牌均重挂编辑面；复盘底稿变化重置候选叙述。
会话身份切换仍由现有 `SessionBoundary` 卸载保护树并刷新账号缓存，不另建账号机制。

## 13. DO-01 标题概要与两层操作（2026-11-26）

`ModuleHeadline.description` 承载轻量概要，复用战略域已有概要样式。数字用 info 语义底色，
需关注用 warning，文字沿用 body token，竖线分组；无新的硬编码字号、色值、间距或 token。
薄封装 `BusinessSummary` 区分静态数字与有真实去向的链接／按钮，浮层沿用正常阅读宽度和
视口上限。原主标题和正文容器不新增一层解释卡。

销售规划优先年度公司营收、已纳入区域及草稿／责任状态；不再统计无经营价值的指标条数。
概要遵守所选版本，区域来源仍保留原独立发布身份，历史与待生效分别提示。
重点客户概要随版本／期间／区域变化，对全量可见部署客户去重，不受清单搜索、行动或关注筛选影响；
未知来源单列。版本／期间／区域用紧凑自然宽度选择器，无重复可见 label，保留无障碍名称。

承诺达成概要使用现有授权加载器与请求缓存：常规视图展示正式目标、实际完成和缺口／已达成，
达成率在浮层；所选历史目标仍对比实时商机。团队概览分别表达显式个人配额或可见区域覆盖，
不从人数拆分目标、不加总不同层级。历史视图只展示实际报送次数和所选／最近报送日期。
赢丢概要按期间、区域及日期归属汇总，搜索／结果／原因／登记状态只影响清单与原因分析；
两种日期范围的样本数、结果分类及赢率采用一致的整体口径。待复盘数字清除冲突过滤后直达清单。
