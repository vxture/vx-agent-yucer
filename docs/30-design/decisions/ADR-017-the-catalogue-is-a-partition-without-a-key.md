# ADR-017 - 目录是一个不带功能键的能力分区

- 状态：accepted
- 日期：2026-08-26
- 相关：ADR-001（能力分区划分）、ADR-002（分区映射到 schema）、ADR-014（产品目录）

## 背景

`incr/0007` 建了目录：`yucer_catalog` 四张表加 `yucer_pipeline.opportunity_line`。
ADR-014 当时写得很清楚——**「建一个域，不是给商机加几个字段」**，并给了理由：
目录是跨域被引用的维度，商机、合同、交付、信号匹配都要读它，而它谁都不写。

**但那次裁定只落了 schema，没落分区。** 到 2026-08-26 为止：

- `DOMAINS` 仍是八项，因此 `catalog.*` **不是一个合法的 action id**（类型错误）
- 目录有 **0 个功能键、0 个权限、0 个 action**
- `price_book_entry.floor_price`——按 DDL 自己的注释，这个字段是这张表存在的理由——
  在服务层没有任何东西守着「谁能改它」
- `incr/0007` 对 `price_book_entry` 写了 `REVOKE UPDATE` 却一列都没 GRANT 回来，
  于是这张表自建成起是**只能插不能改**的：价格录进去就再也改不了

## 决策

**目录是第九个能力分区（D9），且它不带功能键。** 它的全部 action 使用
`feature: null`，门控完全落在权限层，为此新增三个权限。

### 为什么是分区

按 ADR-001 的判据——一个对象只有一个归属分区——目录拥有四张表，且没有别的分区可以写它。
它和 `admin` 不是一回事：`admin` 不拥有任何业务对象（`ActionScope` 的注释原话是
「no feature key, no schema and no page of its own」），目录三条里占了两条。
**「不带功能键」说的是它怎么卖，「拥有对象」才是它为什么是分区。**

### 为什么不带功能键

**19 个功能键是完整的商业面**（owner 裁定，2026-08-26）。目录不在其中，因为它不是
一项可售卖的能力，而是链路的基础设施——**不知道自己卖什么就没法卖任何东西**。
ADR-014 从数据侧说的是同一件事：所有人读它，没有人写它。

真正值得区分的问题也不在档位上。「你买没买价目表」不是一个值得问的问题；
「这个人能不能定底价」非常值得问。所以控制下沉一层，落到权限。

### 三个权限，不是两个

| 权限 | 是什么 | 授予 |
|------|--------|------|
| `catalog.read` | 读目录、方案、价目 | 全部七个角色 |
| `catalog.write` | 维护产品与方案 | sales_leader / sales_ops |
| `catalog.price` | **定标价与底价** | sales_leader / sales_ops |

`catalog.price` 单独成权，是本 ADR 最要紧的一条。`domains/catalog/lib/pricing.ts`
已经在算「低于底价要签字」——**因此能移动底价的人，等于能在不批准任何东西的情况下
批准产品里的每一笔折扣**。这与目录里已有的一个划分同形：`sales_rep` 持有
`pipeline.write` 而不持有 `pipeline.forecast`，注释写的是「拥有这条商机，但不对
预测数字承诺」。这里是：能编目录，但不能决定我们不再往下让的那条线。

**刻意不给 `sales_rep`**：底价存在的意义就是约束正在成交的那个人。

`catalog.read` 给到 `viewer`：一个看不见公司卖什么的人也读不懂一条商机，
而目录不含任何客户数据。

## 后果

- `DOMAINS` 八项 → 九项；`ActionScope` 的注释同步改写，它此前断言「第九个分区不存在」
- 新增 6 条 action，全部 `feature: null`
- 权限目录 20 → 23，授权 68 → 79（`incr/0010`）
- `price_book_entry` 的列锁补齐：`list_price` / `floor_price` / `status` / `updated_at` 可写，
  锚列不可写。此前整张表不可改
- 功能键**不变，仍是 19**
- `catalog.test.ts` 的规模断言与分区集合同步更新——四条守卫在这次改动里全部先打红后转绿，
  这是它们该有的表现

## 这次留下的判据

**「已裁定」和「已执行」是两件事，而且中间隔得可能很久。**
ADR-014 在 2026-08-24 就说目录是一个域，两天后才发现 `DOMAINS` 没动过——
期间没有任何东西报错，因为**没人写过 `catalog.*`，所以那个类型错误从未被触发**。

由此得到一条可机器化的收尾检查：**每一份 ADR 落地后，它声称新增的分区 / 功能键 /
权限，都应当在代码里能被找到**。这与本仓已有的那条「每个 `service.ts` 导出函数
有没有非测试调用方」同类——都是在问「说过的话有没有兑现」。

顺带记一条同型缺口，本 ADR 未处理：**ADR-006 写明证据面要加
`account.interaction` / `account.commitment` 两个功能键，也一个都没加**。
后果是整个证据面挂在 `account.manage` 下，而那是免费档的键——
ADR-012 杀死判据要测的那套采集能力，商业上是白送的。这可能是对的，
但它是漏键的副作用，不是一次裁定。留待 owner 决定。
