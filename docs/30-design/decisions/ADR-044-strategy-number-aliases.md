# ADR-044 战略编号独立于周期，存量旧号保留查询

- 状态：accepted
- 日期：2026-11-26
- 来源：owner 明确要求“存量战略也改号，另做迁移并保留旧编号查询”。

战略业务号统一为 `STR-YYYYMMDD-NNN`：北京时间创建日期、工作区内当日递增序号，
与执行周期分离。沿用 ADR-041 的业务号与 UUID 分离原则；创建时可填写企业自有编号，
创建后仍不可通过业务编辑修改编号。同一战略全部草稿和修订版本共用编号。
本决定替代 ADR-039 中“不重编号”的存量处理条款，不放宽内容冻结或归因保护。

增量 0140 独占锁定战略表，将所有存量战略根的旧号映射至原 lineage UUID，
再按根记录的北京时间创建日期及稳定顺序分配新号。分配跳过当前号和所有旧号占用，
包括已存在的 STR 格式自有号，超过每日序列上限则整批回滚。各修订版同步改号。
仅在该迁移事务内暂停战略身份触发器；完成后恢复。事务失败不留下半份编号或解除的锁。
不修改 UUID、状态、edit_token、时间戳、正式快照、发布事件、下游业务记录或关联。

`strategy_number_alias` 以工作区＋旧编号唯一，复合外键指向原战略根。
应用角色仅 SELECT；不能新增、更改或删除映射。数据库创建校验阻止旧号被新战略复用，
正常修订仍沿用当前根编号。不同工作区可有同名旧号，查询只在当前授权工作区内进行。

总览搜索、新建页的 `?no=` 续接及小聿已授权业务检索支持旧号。读取任一版本时携带旧号，
页面展示新号，编号提示保留旧号供核对；旧链接若通过 UUID 定位不受影响。
Header 全局检索目前仅客户、商机，本次不扩大其业务域。

周期只调整显示：年度 `Y2027`、季度 `2027Q1`、半年 `2027H1`，自定义才显示起止日期。
数据库既有周期键和发布快照保持不变；日期范围仍用于日历编辑、检查和悬停说明。

发布须先应用数据库增量，再发布应用；旧应用仍可按 UUID 工作，新应用依赖只读映射表。
本批完成迁移及预览验证，未经 owner 新发布指令不执行生产迁移或创建发布标签。
