# ADR-012 - 采集习惯的杀死判据：覆盖率、不按人拆、观察满六周才裁定

- 状态：已接受
- 日期：2026-08-17

## 背景

这条 ADR 是**补记，也是一次更正**。

[ADR-006](ADR-006-field-evidence-as-its-own-schema.md) 决定把现场证据独立成
`yucer_field` schema。它**没有**规定任何杀死判据——没有阶段划分、没有六周窗口、
没有 50% 的线。那七十二行里一个字都没有。

而 2026-08-16 起，本仓有**九处**代码、注释、工作计划和一句**用户可见文案**
（`messages.ts` 里的「按 ADR-006 的约定，此时不应建二期」）在援引一条 ADR-006 里
根本不存在的约定。判据的三个数字——`minCoverage = 0.5`、`judgeWeeks = 2`、
`windowWeeks = 6`——是那一轮现场发明的，写在一个常量里就当数了。

`CLAUDE.md` 写得很清楚：留白区一旦填上，改动是**产品决策，要走 ADR，不是自由编辑**。
一个决定「二期建不建」的判据，是留白区里分量最重的一块。所以先把它写下来，再让那九处
如实引用。

一次对抗自审（六视角 + 独立质疑者，58 个 agent，31 条确认发现）同时查出这套仪表
**四个互相咬合的缺陷**，四条都已复现。它们一起构成了本 ADR 的技术内容。

## 决策

### 1. 测覆盖率，不测数量

- **覆盖率** = 当周有开放商机中，至少被记了一笔跟进的比例。**这是判据。**
- **密度**（当周笔数 / 当周开放商机数）只作参照，**永远不是判据**。

理由：一个人往一条商机上倒二十条笔记，密度会很好看，而另外十九条商机全黑。由此得出的
「习惯形成了」在唯一要紧的意义上是假的——二期要在每一条商机下面找到证据，不是在某一条
下面找到二十份。

### 2. 刻意不按人拆分，并且写在界面上

不提供按 owner 的分解，将来也不加。

理由：一旦这张表能当绩效看，大家就会**为它而记录**，它就不再测量它要测的东西。这条
不是谨慎，是**加了会让指标失效**——所以它是设计的一部分，不是待办。

### 3. 判定窗口与阈值

| 项 | 值 |
|----|----|
| 观察窗口 | 最近 **6 个完整周** |
| 判定周 | 最后 **2 个完整周**的覆盖率均值 |
| 通过线 | 覆盖率 **≥ 50%** |

**按最近两周而非六周均值判定**：问的是习惯**现在**在不在，不是第一周有没有热情。
每个工具都有第一周。

### 4. 四条硬性质（每一条都是修一个已复现的缺陷）

**a. 进行中的那一周展示但绝不参与裁定。**
否则同一份数据周日晚上读作 `adopted`、四小时后读作 `not_adopted`——新的一周开始了，
它那个几乎空白的零头按全权重计入。**一个会在午夜变的判据不是判据。**

**b. `too_early` 由「观察了多久」决定，不由数组长度决定。**
观察时长从**最早一条已记录交互**算起。原实现测的是 `weeks.length`，而那个值由
`captureByWeek` 生成、恒等于窗口大小——**这个守卫在生产路径上从不触发**。后果是：
一个在既有商机上启用证据面的工作区，会在**启用后几天内**读到二期的杀死判决。

**c. 分母是历史的，不是「此刻开放的」。**
商机是否计入某一周，看它在那一周是否开放，而不是今天是否开放。否则**关掉一条从没被
跟进过的商机，会追溯性抬高过去每一周的覆盖率**，把工作区悄悄推过 50% 的线，而没有
任何人多记一笔。

**d. 没有任何记录时不是 0，是「无法判断」。**
`observedWeeks` 为 null 而非 0——没有观察，就没有可测量的观察长度。0 会读作
「我们看了，什么都没有」。

### 5. 判据落在哪

`portals/app/app/domains/account/lib/capture-metric.ts` 的 `CAPTURE_CRITERION`
是唯一定义处，`/admin/adoption` 是唯一读取处。**改这三个数字要改这条 ADR。**

## 理由

杀死判据的价值全在于**它能被提前引用而不被提前满足**。所以：

- 窗口未满一律返回「观察期未满」，**不返回失败**——一个能提前失败的判据，一定会被
  提前引用，二期会死在三周的数据上。
- 页面展示**全部演算过程**（六周表格、分母、被点名的黑商机），不只给一个结论。一个
  孤零零的分数只会被无条件相信或无条件无视，两种反应都不是决策。**必须有人能用
  这一页自己的数字来反驳这一页。**

## 后果

- 那九处援引改为引用本 ADR，用户可见文案同改。
- 这套仪表的四个缺陷全部在**同一轮**里由同一个人写出并由机器查出。值得记住的不是
  缺陷本身，是**为什么测试没抓到**：那些测试拿着页面永远不会传的参数去调纯函数。
  「分母是历史的」那条断言当时就在测试里，绿着，而产品带着它本该禁止的缺陷上线了。
  新增的断言一律走 `captureAdoption`，即页面真正走的那条路。
- 六周窗口未到期之前，本判据不产生任何裁定，二期也不据此启动或取消。

## 未决

- 六周之后的实测结果如何处置，本 ADR 不预设。判据只回答「够不够」，不回答「不够时
  改采集还是改产品」。
