# ADR-013 - 战略客户是另一种作业方式，它的判断由「什么都没发生」触发

- 状态：已接受
- 日期：2026-08-17

## 背景

现有链路只建模了**一种**销售：

```
信号 ──> 线索 ──> 商机 ──> 赢单 ──> 交付
```

事件驱动，单位是**一个单子**，生命周期以月计。ADR-001 的八个能力分区、ADR-002 的五个 schema、
`30-business-rules.md` 的阶段机与归因规则，全部围绕它。

企业销售还有**另一种**作业方式：一家客户跨年、跨多个商机持续经营，单位是**一家客户**，
生命周期以年计。战略的一个核心动作是**锁定命名客户**——今年要打下哪二十家——然后在
这些客户上部署战役、指定负责人、争取重大项目。

这一层现在完全不存在。`account` 上没有 `strategic` / `named_account` / `key_account`
任何一个字段（`00_baseline.sql` 可查），也没有任何对象承载"我们打算怎么经营这家客户"。

**拿商机去表达它，永远差一层。** 商机是一次交易；客户经营是一串交易加上交易之间的所有
经营动作，而后者恰恰是战略客户能不能拿下的原因。

## 决策

### 1. 客户分层是战略的产出，不是销售的偏好

`account` 增加 `tier`（`strategic` / `key` / `standard`）。锁定为战略客户是 **D1 的动作**，
不是客户负责人自己勾选的标记——否则每个人都会把自己的大客户标成战略客户，这个字段一周内
就失去意义。

写入路径因此是受限的：只有具备 `strategy.plan.approve` 的角色可以升降客户分层。

### 2. `account_plan` - 客户经营计划

一家战略客户一份，承载商机层表达不了的东西：

| 内容 | 为什么在这一层而不在商机层 |
|------|---------------------------|
| 本期目标额 | 跨多个商机，任何单个商机都不是分母 |
| 目标产品线 | 白地图分析的依据（本期要进入哪些产品线） |
| 决策地图的**目标态** | 商机只关心当前决策链；经营计划关心"我们要把它变成什么样" |
| 跟进节奏 | 见第 3 条，这是本 ADR 的核心 |
| 铁三角 | 销售/售前/交付三个负责人，商机只有一个 owner |

### 3. 「什么都没发生」本身就是判断触发条件

这是本 ADR 分量最重的一条。

现有判断引擎的四条对象规则**全部是事件触发**的：

- `stalled:` 停了 50 天**且**对方有逾期承诺
- `unreached:` 有决策人**且**从未出现在任何交互里
- `weowe:` 我方承诺**且**已过到期日
- `quiet:` 有开放商机**且**超过 21 天没有跟进记录

它们都要求先有一个**开放商机**。这对交易型销售是对的——没有在办的单子，客户安静是正常的。

**对战略客户是错的。** 一家被锁定为战略客户的公司，即使当前一个开放商机都没有，
长时间没有高层接触**本身就是最需要报告的事实**：它意味着这份经营计划正在失效，
而失效的过程是静默的，不会有任何事件来提醒任何人。

所以 `account_plan` 带跟进节奏：

- `contact_cadence_days` - 任意一次有效接触的最长间隔
- `exec_cadence_days` - **高层**接触的最长间隔（决策人级别，通常远长于前者）

判断引擎增加第五条规则：

```
战略客户 且 (距上次接触 > contact_cadence_days 或 距上次高层接触 > exec_cadence_days)
```

**不要求存在开放商机。** 这是它与 `quiet:` 规则的根本区别，也是它存在的全部理由。

### 4. 节奏是计划的一部分，不是全局常量

每家客户的合理节奏不同：一家正在投标的客户和一家刚交付完进入平稳期的客户，
用同一个天数是错的。所以节奏写在 `account_plan` 上而不是配置里，
默认值由创建计划的人选定并可随经营阶段调整。

改节奏是**经营决策**，会留在计划的更新记录里；它不能被用来悄悄消掉一条判断——
这与 ADR-003「提案不可篡改」是同一条原则的延伸。

## 后果

- **判断流会出现没有商机的客户。** 这是有意的。首屏的「今天有 N 件要你定」从此包含
  "一家战略客户三个月没见过高层"，它和"某个单子停了 50 天"同等重要，甚至更重要。
- **白地图分析要等产品体系。** 计划里的"目标产品线"在产品域建成前只能是文本，
  真正的"买了 A 没买 B"要等 `opportunity_line`。这一条**不在本 ADR 范围内**，
  记在这里是为了说明为什么计划里先放了这个字段。
- **分层写入受限于 `strategy.plan.approve`**，意味着客户负责人**不能**自己把客户升为战略客户。
  这会带来摩擦，是刻意的：不受限的分层等于没有分层。

## 备选方案

**在 `account` 上直接加节奏字段，不建 `account_plan`。** 更小，但把"经营计划"降级成了
两个天数。目标额、目标产品线、决策地图目标态、铁三角都无处安放，而这些正是战略客户
区别于普通客户的内容。真正需要的时候再补一张表，等于让第一版的判断规则建立在一个
注定要改的形状上。

**用现有 `quiet:` 规则加一个"战略客户放宽阈值"。** 看起来最省事，但它保留了
"必须有开放商机"这个前提，而那正是要推翻的东西。放宽阈值解决不了
"没有单子的战略客户彻底消失在雷达外"。
