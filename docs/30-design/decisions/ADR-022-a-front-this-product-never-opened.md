# ADR-022 - 任务表删除：一条产品从没声明要开的战线

- 状态：accepted
- 日期：2026-08-28
- 相关：TD-016（门后面没有动词）、ADR-001（能力分区）、
  `docs/20-specs/10-product-definition.md`（yucer 是销售超级智能体）

## 背景

TD-016 普查出 14 个「声明了门、背后没有动词」的 action。逐条还的过程中，
`delivery.task.upsert` 显出它和其余几条**不是同一形状**。

| | 其余各条（区域 / 联系人 / 里程碑 / 商机创建） | `project_task` |
|---|---|---|
| 表 + 列锁 + action | 有 | 有 |
| 记录类型 | 有 | **无** |
| 端口方法 | 至少有读 | **无** |
| 界面 | 至少读得到 | **无** |
| demo 数据 | 有 | **无** |
| 任何一条 ADR 提到过 | 有 | **无** |

其余各条是「**中间缺一段**」——两头都在用，把动词写出来就还上了。`project_task`
**只有两头**：批次 1 建模时一次性铺开，此后七个批次没有任何东西碰过它。它是
`yucer_delivery` 里唯一有这个性质的表（`project` / `project_milestone` /
`revenue_schedule` 都被读，其中两张现在还被写）。

## 决策

**删掉表、列锁与 action，不建这个功能。**

### 为什么不建

**yucer 是销售超级智能体。** 任务管理是交付/项目管理工具的领地。建它要先回答一串这个产品
从没打算回答的问题——任务是干什么的、谁指派、和里程碑什么关系、逾期了谁负责——那不是还债，
是开一条新战线。

批次 1 的建模把「一个交付项目大概需要什么」一次性铺开了。里程碑和回款后来被证明是对的
（健康度规则读里程碑，回款面板读分期）；任务没有。**一个七个批次没人碰过的表，是当初猜错
的证据，不是待办事项。**

### 为什么不留着

留着不是零成本，是**一份长期站着的谎**：

- 一道门着空气的门（`delivery.task.upsert` 挂在 `delivery.project` 功能键上，STARTER 档
  起售）；
- 数据设计文档里一张读者到不了的表；
- `gated.test.ts` 白名单里一条永远不会被删的记录——而那份名单的价值恰恰在于**它会变短**。

删掉的成本是一个增量。真需要时，那时候的需求会比批次 1 的猜想准得多，而重建的工作量和
现在建是一样的。

## 怎么删的

**基线也改了**，而 `incr/README.md` 一般禁止这件事（`00_baseline.sql` 是 create-once）。
这里安全，理由是可核对的事实而不是判断：**这套 DDL 从没建出过任何一个数据库**——
0 个部署环境、0 个发布 tag、0 次 db-init 运行。

只用增量 DROP 而保留基线的 CREATE，会让每次 db-init 都「建了再删」，中间 `98` 还去锁一张
注定被删的表。既然没有任何数据库存在，把它从基线和 `98` 一起摘掉才是干净的状态。

`incr/0014` 仍然发了 `DROP TABLE IF EXISTS`，为的是任何**已经**应用过旧基线的检出也能收敛。

### 顺带补上一个守卫的盲区

`check-data-architecture.mjs` 把基线与全部增量拼起来，只找 `CREATE TABLE IF NOT EXISTS`——
**它不认识 `DROP`**。也就是说：任何人按 README 的规矩「只在增量里 DROP」，这张表都会永远
留在它的集合里，而**第一次这样的删除会被报成 Prisma 漂移**；更糟的是，对那份报告最自然的
反应（把 Prisma 模型删掉）会让报告变得更红而不是更绿。

已改为按文件顺序读 CREATE 与 DROP，后者胜。反证过：撤掉 DROP 支持，两条新测试立刻变红。

## 后果

- `yucer_delivery` 从四张表变三张；数据文档与能力分区文档同步。
- TD-016 从「10 条待还」变成「6 条待还 + 1 条已裁定删除」。
- 功能键仍是 19：`delivery.project` 不变，它本来就覆盖项目与里程碑。
- 权限目录不变：`delivery.write` 仍在用，只是不再有一个指向空气的 action 挂着它。

## 被否掉的方案

**建一个最小任务 CRUD 把门填上。** 那是让指标好看，不是让产品更对。一个没人设计过的功能
建出来就是下一个七批次没人碰的东西，而且这次还带着界面。

**留着表、把 action 删掉。** 半个删除。表仍在数据文档里、仍在每次 db-init 里被创建，而
读者仍然到不了它——省下的只有一行白名单。
