# ADR-038 - 销售规划按整份计划发布版本，历史达成绑定采用的目标

- 状态：设计确定，待实施
- 日期：2026-11-11
- 依据：owner 要求以区域整合目标、客户和团队，并管理调整版本
- 关联：ADR-020、ADR-021、ADR-030、ADR-031
- 规格：[区域销售规划与版本管理](../../20-specs/35-sales-planning.md)

## 背景

现有 sales_target 按周期/作用域/指标唯一，金额在原行更新，没有目标修订历史。
plan_id 已引用 D1 strategy_plan。它不能直接换成 D2 规划版本 ID，唯一键也不能通过追加
同一作用域的记录来绕过。区域、客户贡献和团队投入分开改，会让同一公司目标引用不同基线。
历史预测虽然追加保存，目标若取今天的值，过去的达成率仍会被今天的调低目标改写。

## 决定

1. D2 新增稳定的销售规划身份及独立修订对象。一个版本包含公司及所有区域的完整计划。
   区域编辑是草稿内的局部操作；目标跨区调拨、客户贡献和资源变更一次发布。
2. 草稿可更新，冻结版本及其子项不可更新/删除。一个共享草稿使用乐观锁；发布使用根记录锁、
   预期基线和幂等键，冻结内容、分配版本号及发布事件同事务提交。
3. 当前版本从有序的发布/生效/取消事件解析。支持未来生效，禁止回溯改目标；恢复旧方案
   产生新版本。定时生效正确性不依赖后台任务维护一个可漂移的 current 指针。
4. 当前视图可比较原始基线与现行目标。D6 新的预测提交同时保存不可变的目标依据，引用
   实际读到的 D2 修订及目标内容；快照与依据由 D6 同事务写入，D6 不写 D2 的规划表。
5. 地域范围、客户计划来源和团队配置在版本中留快照，主数据变化仅作为下一版的变更输入。
   冻结快照的读取仍执行当前权限和数据范围规则。
6. 现有目标以显式接管映射迁移。接管后的写入口转为规划草稿；不双写两份目标权威，不修改
   旧目标 ID、作用域身份或旧预测快照，不把历史无绑定数据补造为 V1。

## 取舍

选择年度整份规划作为发布边界，保障公司/区域分配和共享人员检查一致。区域很多时需要局部
编辑和差异筛选，但不因此让不同区域各自决定全局的生效基线。独立区域草案可在后续作为
同一根草稿的输入，不能绕过整体发布校验。

采用完整冻结快照，不只保存差异补丁：读取任一版本不必回放所有修订，引用源后来改名或
消失也能解释当时计划。差异为派生结果，摘要保留比较版本与算法版本，不作为恢复的权威。

发布不新增强制审批层级；使用现有规划维护权限。若未来区分编辑/发布权，必须按既有种子、
类型镜像、动作目录、权限文档同步变更，不能借用 D1 strategy.approve 暗中扩大权限。

## 后果与验收

新结构及冻结约束必须通过实际数据库事务测试。重点验证并发发布只成功一次、发布失败无
半份版本、定时调度取消与替换、过期草稿冲突、关闭周期不可改、跨工作区引用拒绝、历史
达成不随新目标漂移以及重试不产生多份版本。

本 ADR 记录设计，不构成 DDL 已执行或版本管理已上线的证据。
