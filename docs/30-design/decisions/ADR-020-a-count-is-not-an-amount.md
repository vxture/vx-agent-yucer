# ADR-020 - 计数不是金额，指标必须自己决定分子

- 状态：accepted
- 日期：2026-08-28
- 相关：TD-013（登记）、TD-014（本次查出、单独登记）、ADR-014（行项权威）、
  incr/0013（落地）

## 背景

`sales_target.metric` 有四个值：`revenue` / `new_logo` / `pipeline` / `margin`。
`SalesTarget.targetAmount` 只有一个类型 `Money`，带 `currency`。

`new_logo` 是**新客户数**——十个新客户不是十块钱，也没有币种。但 `Money` 是当时唯一
可用的形状，于是表单向它要一个金额，表格把 10 渲染成 ¥10，库里每一条计数目标都带着
一个无意义的币种。这是 TD-013 登记的内容。

**登记的只是症状。** 检查类型时才看清：**`metric` 从来没有进入达成率计算**。
`attainment(closed, target)` 由调用方挑分子，每个调用方都挑了同一个——快照的
`closedAmount`。实测一条「新客 10」的目标：

```
| 全工作区 | 新客户数 | ¥10 | ¥2,700,000 | 27,000,000% | 草稿 |
```

四个指标里三个的数没有意义，而且都以百分比的形式呈现给读者。

## 决策一：一张表，单位由指标推导，不存列

TD-013 给了两条修法。取第一条。

`unitOf(metric)` 是**纯函数**，`new_logo` 是 count，其余是 money。数据库**没有**
`unit` 列：存下来就是第二个真相源，可以和旁边的 `metric` 打架，而每个指标只有一个
正确答案。

拆成两张表（第二条修法）要为**一个**指标复制整套作用域元组、状态机、唯一约束和
`/planning` 的联合查询。一个指标的单位不同，不足以让它变成另一种东西。

`target_amount` 保留原名。它对一个指标存的是计数，而跨 Prisma 和每一处查询改名换不来
TS 类型已经给的东西：

```ts
export type TargetValue =
  | { unit: "money"; amount: number; currency: string }
  | { unit: "count"; amount: number };
```

判别联合而不是 `{ amount, currency: string | null }`，因为重点是**把计数格式化成货币
必须编译不过**。`currency` 根本不是 count 那一支的属性，没有任何代码能从它上面读出
一个币种来。

`currency` 列改为可空，并加 CHECK 把可空性和 metric 绑死（incr/0013）：计数目标必须
没有币种，金额目标必须有。错误状态不可表示，不是不鼓励。

服务层收**数字**不收 `Money`，单位由它按指标推导。TD-013 的成因就是「形状由调用方
选，而可选的形状只有一种」。

## 决策二：分子由指标决定，没有分子就说没有

| 指标 | 分子 | 说明 |
|------|------|------|
| revenue | `closedAmount` | 不变 |
| pipeline | `pipelineAmount` | 原来用成交额，等于按「已经不再是管道的部分」给一个建管道的目标打分 |
| new_logo | `new_logo_count`（快照新增） | 见决策三 |
| margin | **没有** | 成本尚未进入模型。界面报「需补充成本」——见下方 2026-08-28 的补充裁定 |

`measure()` 返回判别联合，不返回数字：

```ts
type Measurement =
  | { kind: "measured"; achieved: TargetValue; ratio: number | null }
  | { kind: "not_measurable"; code: "no_snapshot" | "no_cost_data" | "not_counted" };
```

**一个错的数以百分比呈现，比一个诚实的空白更糟**——只有空白会告诉读者不要据此行动。
三种「没有数」用三个不同的码，因为读者该做的事不同：等一等、去提交快照、或者别再指望
这个指标有数。

**这个函数落在 D2 不落在 D6。** 旧的 `attainment` 住在 `pipeline/lib/forecast.ts`，
那正是 `metric` 被忽略的原因：调用方挑分子。成立的划分是——**D6 发布数字，D2 决定自己
的指标量哪一个**。两个域仍然不互相写对方的数据，那条规则从头到尾没变。

## 决策三：新客 = 本期首次赢单的客户

两半都要紧：

- **首次是全工作区判定**，不是「在本区首次」。否则同一个客户在两个大区各被赢一次，
  公司的新客数会超过它实际获得的客户数。
- **归给那一单所在的作用域**。功劳跟着破冰的那一单走，那也正是目标所针对的那一单。

因此 `countNewLogos` 收**未过滤**的机会列表加一个作用域，而不是收一份过滤好的——第一
个条件在过滤后的列表上无法判断。

存在快照上而不是读时算，理由就是快照存在的理由：达成率读 D6 已经发布的数，D2 不重算
一个已经有主的数字。

`new_logo_count` **可空且无默认值**。0 会在两处说谎：本增量之前的快照（没人数过），
以及周期标签解析不出日期的快照。「没人数过」和「数出来是 0」是两个事实，把它们合并
和把「未提交快照」报成「达成 0%」是同一个错误。

## 顺带：两处同型缺口

战况板配额卡与 `/planning` 首行都写了内联 `.find()` 取「第一条已承诺的工作区目标」,
不看指标，然后按货币格式化并参与除法。提为规则层的 `summaryTarget()` 并配单测。

当前行序恰好让收入目标排在前面，所以它是**潜伏**而非已发作；把收入目标关掉，唯一
已承诺的工作区目标就是那条计数目标。写在这里是因为「今天的排序刚好躲开了」不是设计。

## 被否掉的方案

**计数指标搬到另一张表。** 见决策一：为一个指标复制整套元组。

**存一个 `unit` 列。** 第二个真相源，可以和 `metric` 不一致。单位是指标的纯函数。

**给毛利编一个分子。** 用成交额当毛利的分子正是本 ADR 要消灭的东西。没有成本数据就
是没有；把 margin 从指标里删掉是产品裁定，留待 owner 决定，本 ADR 不代做。

## 补充裁定 2026-08-28（owner）：毛利留下，措辞改为「需补充成本」

上面把 margin 的缺口留给 owner 决定。裁定是：**指标留下，界面说的是缺什么，不是说这
个指标不能算。**

`no_cost_data` 这个码不变——它一直就是准确的。变的是它渲染成什么：

| | 原来 | 现在 |
|---|------|------|
| 标签 | 不可测 | 需补充成本 |
| 提示 | 「这个指标目前无法度量」 | 「毛利需要成本，而成本目前还没有进入模型……补上成本它就能算」 |

区别不是修辞。**「不可测」是关于这个指标的陈述，「需补充成本」是关于这份数据的陈述**,
而事实是后者：毛利完全可以算，缺的是一个还没接上的输入。前者会让读者不再指望它，也就
不会有人去补那个输入——一个描述成永久属性的缺口，没有人会去修。

这条同时收紧了本 ADR 决策二里「没有分子就说没有」的说法：**说没有分子，不等于说这个
指标没有分子可言。** 三个 gap 码现在各自对应一件不同的、读者可以做的事——等一等
（`no_snapshot`）、去提交快照（`not_counted`）、去把成本接进来（`no_cost_data`）。

**顺手把金额总额也按周期过滤。** 那是 TD-014，会改变屏幕上已有的数字，需要独立验证。
本 ADR 只引入 `periodRange()` 并用于新客计数；不一致是显式登记的，不是藏起来的。
