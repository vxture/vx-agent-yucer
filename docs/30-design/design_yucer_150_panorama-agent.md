## 1. 形态前提

> 智能体的产出不是右栏一个挂件，是每一层的内容本身。

| 产出 | 长在哪 | 不长在哪 |
|------|--------|---------|
| 汇总句 | L5 评估层顶部，作为判定 | 不是右栏的一条消息 |
| 判断 | L5，以及待裁决队列 | 不是弹窗提示 |
| 提案 | L6 作战方案 | 不是每张卡角落的小灯泡 |
| 证据引用 | 每一句判断背后，可展开 | 不是单独一个「数据来源」页 |
| 对话 | 右栏面板 | 这一项确实归右栏 |

右栏只承担两件事：**把正在等你裁决的端到面前**，以及**接住随手记的一笔**。
它不是智能体的全部出口。

## 2. 六级阶梯

| 级 | 能力 | 产出形态 | 授权 | 现状 |
|----|------|---------|------|------|
| L1 | 汇总 | 一句陈述句，不含建议 | 自主 | 已有 |
| L2 | 判断 | 断言 + 来源 + 证据引用 | 自主 | 已有 |
| L3 | 提议 | 动作 + 理由 + 置信度 + 能力分组 | 自主产出，不自动执行 | 已有 |
| — | **ADR-003 的线** | 线以上智能体做完并呈上；线以下**必须先有人签字**，顺序不能反 | | |
| L4 | 代办 | 起草邮件、更新字段、发会议邀请 | **需人裁决** | 缺 |
| L5 | 对话 | 答案 + 它引用了哪几条 | 只读，不受线约束 | 有入口 |
| L6 | 预演 | 推演结果，**明确标为推测** | 只读，不受线约束 | 缺 |

**L5 / L6 不在线下，因为它们不写任何东西。**只读能力的边界是**它读得到什么**，
不是**它能不能动手**——所以对话必须受同一套门控约束：用户看不到的账户，助手也不能
替他回答。

## 3. 成分要求

判断的三要素与提案的四要素见 `design_yucer_140` §5，此处不重复。本文只补一条落地
观察：

> **已知的一处偏差**：目前 `draft_outreach` 这类动作的能力分组来自一张静态映射表，
> 导致一条健康触发的触达提案被标成「决策链测绘」。分组错了，人签字前对动作性质的
> 预期就是错的。已判定为架构问题留待以后（owner，2026-09-21），但它属于「提案四
> 要素」的违反案例，不是可接受的现状。

## 4. 必须说「我不知道」的三种情形

智能体产品最大的信任杀手不是答错，是**在没有依据时假装有依据**。

| 情形 | 必须这样说 | 不许这样说 |
|------|-----------|-----------|
| 没有数据 | 「尚未侦察。竞争对手目前只出现在跟进原文里，还没有成型情报」 | 编一个名字，或「暂无数据」了事 |
| 数据太旧 | 「这条判断依据的是三个月前的事实」 | 用陈旧事实产出语气笃定的现在时判断 |
| 多源冲突 | 「两条跟进对这件事说法不一致，需要你确认」 | 挑一条当真相，悄悄丢掉另一条 |

**后两种目前都做不到**——证据新鲜度标记与多源冲突提示都还没有。它们不是锦上添花：
没有它们，L2 的判断在数据变旧或打架时会**静默地给出错误的确定性**。

## 5. 代办的三重同意

L4 代办真正落地时，「能不能自动」由三个条件同时成立决定，缺一不可，且第三条不能被
前两条覆盖：

1. 套餐里有这个能力（功能键层面）
2. 这个人有这个权限（权限层面）
3. 这件事被明确允许自动做（动作层面的单独同意）

仓库里已有这个三重判定的实现，L4 上线时直接复用，不另起一套。

**即便三重同意齐了，代办也只在签字之后执行。**三重同意解决的是「能不能自动」，
ADR-003 解决的是「什么时候自动」——答案是：人签了字之后的执行环节。
不是替人做决定，是替人跑腿。

## 6. 出处与可信度

L1–L3 是对既有实现的成文化；L4 与 L6 是设计，尚未实现；L5 目前只有入口。
§4 的后两条依赖证据新鲜度与冲突检测，两者都还没有。
