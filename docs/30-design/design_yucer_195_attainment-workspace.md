# 承诺达成：目标、预测与复盘的一体工作流

状态：原统一工作区已实现；销售规划承接的读模型、页面和报送确认已实现，尚未发布。验收见
[承接实施计划](../70-workplan/35-attainment-planning-handoff.md)。
产品依据为 `20-specs/30-business-rules.md` 第 2 节与 `20-specs/35-sales-planning.md`。
D2 设置目标，D6 持有商机和不可变预测快照；入口统一不调整拥有域、能力键或动作权限。

## 业务顺序

1. 销售规划中设定并承诺目标：周期、范围、收入指标、金额及币种。
2. 查看已发布目标进度：同范围、同周期最近一次提交的成交额对照目标。
3. 检查当前支撑商机：实时成交与剩余缺口，按承诺、乐观、早期管道查看开放商机，判断覆盖。
4. 检视预测：对照填报、规则及依据，决定逐笔分类调整；规则不会自动覆盖人的判断。
5. 提交预测：明确周期、范围与币种，复核实时分类汇总，可补负责人预估和说明；追加历史记录。
6. 复盘：查看历史预测、金额变化、期初承诺兑现率；周期结束后评估预测准确率。

已关闭目标继续作为历史基准展示，草稿目标不计入达成。没有目标仍可检视商机和提交预测，没有快照不等于达成率为零。目标为零时保留成交额，
不显示虚假的百分比。设置目标仍在销售规划中，不复制第二套目标编辑器。
客户往来承诺及其逾期、兑现仍留在客户与商机界面，不计入本模块的销售目标百分比。

## 周期和统计范围

周期保留「全部 / 当年 / Q1 / Q2 / Q3 / Q4」，年度随系统时间变化。
「全部」将各周期目标进度列为独立行，不累加包含关系中的年度和季度，不平均达成率；
检视、提交、复盘需先选择一个明确周期。没有目标的周期也可通过周期控件进入预测。
历史目标的周期链接继续可达，不因当前年份而悄悄替换周期。

团队与我的共用一个范围模型：工作区、区域、负责人；「我的」解析为当前登录人的负责人范围。
同一范围驱动目标选择、已发布进度、实时商机、产品拆分、预测检视、提交和右侧预测提示。
统计范围选择不授予权限；所有读取和写入仍通过原领域服务。

旧 `/forecast?period=...&scope=...` 重定向到统一工作区的预测检视，保留周期和范围。
旧达成链接的 `scope=team/personal` 继续兼容。内部 `forecastRule` 注册保留作升级门禁使用，
不再成为独立 Launcher 模块。

## 数字契约

| 名称 | 分子 / 分母或来源 |
| --- | --- |
| 目标达成率 | 最新已提交快照成交额 / 同范围同周期已承诺收入目标 |
| 已发布缺口 | max(目标 - 最新已提交成交额, 0) |
| 当前成交 | 当前商机按实际成交日过滤后的赢单额 |
| 当前缺口 | max(目标 - 当前成交, 0) |
| 缺口覆盖倍数 | 当前开放商机总额 / 当前缺口；目标已覆盖时不显示无穷大 |
| 期初承诺兑现率 | 当前实际成交 / 期初快照承诺额；允许超过 100% |
| 预测准确率 | 原领域规则按实际与期初预测的偏差计算；周期结束后展示 |

已发布与实时分区明确标示，不将两种时点混作一个“已完成”。开放商机按预计成交日，
赢单按实际成交日；丢单、放弃不贡献成交，未填日期单独提示。四类金额互斥，不嵌套累加。
币种不一致时拒绝合计与覆盖计算，仍允许逐笔查看各自币种。产品构成只读取同批开放商机行项，
不把无行项或无权限误报成已计入。读取失败明确展示，不用零值代替。

特别注意：现有 planning.attainment 的 publishedTotalsFor 返回最新快照金额，但不返回该快照
ID、时间和目标依据，measure 使用当前 TargetRecord。因此现有概要只能解释为「最近报送金额按
当前目标重算」，不能标为「当时考核成绩」。本次必须改成可识别快照与分母的读模型，而非只补标签。

### 2. 业务主线与边界

```mermaid
flowchart LR
  A[销售规划发布 Vn] --> B[承诺达成：目标与执行缺口]
  B --> C[客户与商机：推进和反馈]
  C --> D[预测检视：核实分类与证据]
  D --> E[提交预测：冻结快照及目标依据]
  E --> F[历史复盘：按当时依据评价]
  F --> G[需要调整目标或资源]
  G --> H[销售规划：调整草稿并发布 Vn+1]
  H --> B
```

- 销售规划回答「要完成多少、在哪些区域、依靠哪些客户与资源」。
- 承诺达成回答「已经完成多少、剩余缺口由哪些商机支撑、承诺是否可靠、下一步做什么」。
- 正式目标、预测分类 commit、客户往来承诺是三个对象。保底目标不自动转成 commit；
  发布规划不自动生成商机、不替用户提交预测，也不把规划行动自动标为客户承诺。
- 修改金额、区域边界、计划资源或期限回销售规划生成新版本；执行反馈只更新原有执行对象。
- 地域、组织和人员分开：两个人可支撑五个销售区域；部门只表示组织责任，不生成销售区域。

### 3. 视角与入口

保留「团队 / 我的」及原来的三个内部视图，不新增顶层模块。周期继续保留「全部」。

| 视角 | 目标依据 | 主要内容 | 不能做的推导 |
| --- | --- | --- | --- |
| 团队负责人：公司 | 当前生效规划的公司同周期目标 | 公司进度、区域对照、未归属业绩、风险与支撑 | 不能把公司和区域目标或业绩重复相加 |
| 团队负责人：区域 | 当前生效规划中该稳定区域的同周期目标 | 区域进度、客户支撑、团队与行动安排、商机 | 不能把部门业绩当地域业绩 |
| 个人 | 独立且正式的 owner 同周期配额；保留来源说明 | 我的进度、我的商机、我的预测、与我相关的规划行动 | 不能用区域目标除以人数，也不能把支持区域全额算作个人目标 |

团队和个人为同页不同数据范围，不是一套可相互加总的报表。没有个人配额时显示「尚未分配个人目标」，
仍可查看自己的商机与提交预测；调整入口复用现有个人目标能力，不能送入公司目标编辑并悄悄改范围。
达成进展的「团队」为总览：公司及全部可见销售大区同时展示，周期明细默认展开，
不再要求下拉逐个选择。工作区范围可看公司及全区；地域/组织受限成员默认进入其授权区域总览，
不下发公司总额或其他区域；仅本人范围默认「我的」。出现在规划团队清单不增加访问权。
预测检视、历史复盘与报送仍绑定具体公司/区域/负责人范围，不把总览当成可提交的合成范围。

部门为独立的组织责任维度，主页面不在公司→地域下再加部门金额层，以免一部多区、多部一区时重复统计。
后续部门明细采用抽屉组织树（部门→子部门→成员），列明各区投入与负责商机，并保留原地域归属；
部门统计按成员/商机去重，不将地域目标复制成部门目标，也不从支持关系生成部门配额。
该部门树为设计方向，本轮不新建部门考核口径。

#### 4.1 目标与周期进展

- 一张 DS MetricListCard，四个轻量指标区：正式目标、当前成交、当前达成率、当前缺口。
  正式目标金额最突出；保底和挑战在其下同一行辅助展示，缺失显示未设定，零保留为零。
  个人无三档时仅显示真实配额，不补假档位。人员不占第五张成绩卡。
- 当前版本及币种置于标题区；原始基线差异、三档详细缺口、发布时间、分配情况在「目标依据」抽屉。
  当前率明确是实时金额按现行目标计算，不覆盖报送成绩。超过目标保留实际比率，进度条最多填满。
- 年度下方沿用规划的周期折叠组件。未展开时「周期进展」为小号淡色，显示已拆分周期数；
  展开后标题增强、计数消失。周期触发行保留浅色虚线；折叠内容区内部的分隔线和留白随内容收起，不留空底。
- 周期表：序号、周期、正式目标、当前成交、达成率、缺口、操作。序号列头留空，首末列 64px 居中。
  保底/挑战可以在目标单元格辅助展示，金额与同类列对齐；不把同一季度拆成三条业绩。
- 单季度不再展开重复的自己；「全部」按年度分组列出各周期，提供版本来源，不跨周期算总数或平均率。
  不自动进入当年，不让「全部」消失。未规划季度仍可切入检视商机，但不拿年度目标除以四。

#### 4.2 报送信息的位置

达成进展保留一行轻量报送摘要，不再叠加一整套「已发布目标进度」卡。摘要包含快照时点、
当时目标版本、当时成交和当时报送达成率；依据缺失或目标为空则按真实状态显示。
当前规划与快照版本不同，直接提示「规划已调整，报送依据为 V1」，查看抽屉解释差异。
预测检视围绕当前支撑与待提交内容；历史复盘则将所选快照及其目标依据提升为主摘要。
三视图各用一份相应上下文的摘要，历史页不混入当前目标卡和当前助手简报。

#### 4.3 区域进展

- 团队总览同时展示全部获授权销售大区，支持标准 DS 卡片/列表；地域/组织受限时仅展示可见区，
  不通过区域相加伪造公司总额。「全部」同时列出公司各周期与各大区年度/周期；具体区域深链继续可用。
  复用规划卡片的标题结构：区域图标、名称、必要风险摘要、三点菜单一行；不展示省份长清单。
- 区域以已生效规划冻结快照为目标来源。改名、停用、重新划区不自动移走本期目标和历史金额；
  详情可对照当前配置。尚未纳入规划但确有业绩的区域另列「无目标区域」，不隐藏成交。
- 目标三档、成交、缺口、承诺均使用相同币种及周期。当前达成率以正式目标为分母；
  待成交承诺指 commit 开放商机，不包含已成交，不称为已完成。
- 整个列表信息行可展开周期，保留 Enter/Space 操作和展开态背景；仅触发按钮有 hover 反馈。
  卡片/列表共用展开状态；链接、菜单、文本选择不误触展开。
- 公司金额取公司完整授权范围的原始业绩，不通过相加可见区域凑出。显示未归属金额与区域
  对账差额；仅在权限、观察时点和口径一致时计算对账。个人金额不与区域金额再累加。
- 状态限于确定事实：已达标、未设目标、缺口覆盖不足、存在承诺风险、数据不足。
  不以年度已过百分之几线性推算「落后」；未来节奏预警必须有正式周期拆解或明确假设。

#### 4.4 支撑内容与下一步动作

主区以商机支撑清单为执行入口；产品构成降为按需展开，不和主表争首屏。
商机标题及客户副标题各自可点击，hover 只变强调色，无下划线；行操作保留打开商机工作台。
金额紧跟标题，分类/预计成交/负责人后置；风险详情抽屉，不横向塞入长段证据。

规划中的三类支撑从区域或目标三点菜单进入一个「规划支撑」抽屉，内部按需切换：

| 内容 | 计划 | 执行事实及操作 |
| --- | --- | --- |
| 客户贡献 | 发布版的客户、贡献预算、责任 | 已明确关联且同范围同周期的商机、成交；跳客户或商机详情。跨区预算不能替代实际归属 |
| 团队与资源 | 计划人员、需求岗位、FTE | 已指派成员及待补缺口；人数去重。已配置人员不表示已发生相同投入或费用 |
| 行动安排 | 发布版行动、责任、期限、支撑对象 | 仅展示有明确关联的跟进/承诺证据并跳转；无关联显示「暂无执行证据」，不推断未执行 |

现有计划只保存 planned_evidence_refs，尚无完整执行证据关联工作流。首期只读已有明确引用，
不靠客户名或文字相似度认领事实，不为此新增一套行动管理器。助手后续可建议关联，仍须按
现有人类确认链执行。执行证据自动关联属于后续阶段。

### 5. 口径与版本契约

| 显示名 | 算法与依据 | 所在位置 |
| --- | --- | --- |
| 当前达成率 | 当前成交 / 当前生效正式目标 | 达成进展主摘要，显示观察时点与 Vn |
| 当前缺口 | max(现行正式目标 - 当前成交, 0) | 主摘要与区域清单 |
| 当时报送达成率 | 所选快照成交 / 该快照实际保存的目标金额 | 最近报送行、历史复盘；不使用现行分母 |
| 待成交承诺 | 同范围周期开放商机中 commit 金额 | 商机支撑；与已成交分别展示 |
| 承诺支撑后缺口 | max(现行目标 - 当前成交 - 待成交承诺, 0) | 支撑详情；明确为预测推演，不能叫实际缺口 |
| 缺口覆盖倍数 | 同口径开放商机总额 / 当前缺口 | 商机支撑；缺口为零显示目标已覆盖，不显示无穷大 |
| 期初承诺兑现率 / 预测准确率 | 沿用 D6 已有规则与参考快照，显示参考时点 | 历史复盘；不因为切换目标版本改变预测参考快照 |

例如 V1 目标 1,000 万，报送成交 400 万，报送达成率为 40%；V2 调为 800 万，
实时成交仍为 400 万，则当前达成率 50%，历史 V1 仍为 40%。若原始与现行地域边界不同，
仅展示两版目标及边界差异，不把现行地域金额硬套原边界生成可比率。

目标为零不计算百分比；未设目标、无快照、读取失败、无权限分别表达，不以零替代。
未配置季度目标不拆年度值；不同币种分别展示、不偷偷汇率换算。名称 revenue 沿用现有成交
金额语义，不宣称财务确认收入、开票或回款。新客/管道/毛利使用各自正式度量，未具备分子时
显示数据不足，不能用成交金额复用一切指标。

读模型要求：一次服务端编排固定 observationAt 和规划时间线，返回 scope、period、metric、
currency、stable lineKey、current revision、original baseline、tiers 及来源状态；当前商机以同一
请求读取，不声称与规划有跨域数据库事务。报送另返回 snapshotId、snapshotAt 和原始 TargetBasis。
基础目标元数据用最小授权投影，不能让区域/个人用户绕过 readSalesPlan 的完整工作区权限读取全版
客户和人员。完整版本仍遵循原有权限；预算、客户和成员明细各自检查源权限。

### 6. 提交、跳转与操作闭环

提交仍称「提交预测」：不把已发布销售规划再次发布。确认面板展示周期、范围、币种、目标版本及
正式目标，四类系统汇总只读，保留现有负责人预估与说明；无目标仍可提交并明确记录 none。
确认使用服务端生成的短期上下文凭据绑定 scope/period/currency 与目标依据指纹，提交时重新验证。
若生效版本或用于确认的金额已变化，返回重新核对状态，保留说明；不得静默换成另一版目标后提交。
最终原子保存采用的依据与快照；要避免确认后再解析发生变化，写入必须使用已校验的同一份依据。
首期不承诺跨 D2/D6 事务串行；恰在校验后生效的新版不会覆盖这次实际确认的不可变依据。
网络未确认时沿用现有失败恢复，并补幂等提交标识，防止用户重试重复追加同一报送。

| 入口 | 操作项 | 结果 |
| --- | --- | --- |
| 公司/区域目标 ⋮ | 查看目标依据、查看规划、调整规划（有权时） | 抽屉只读来源；查看定位发布版；调整显式进入共享草稿，不能直接修改目标 |
| 公司/区域目标 ⋮ | 展开/收起周期进展 | 与整行/按钮共用状态，零周期显示原因 |
| 公司/区域目标 ⋮ | 查看规划支撑 | 定位本范围/周期的客户、团队、行动；无权限只显示可见部分 |
| 区域信息行 | 查看该区域达成 | 保留周期，切换到同页区域范围；不新建第二份区域工作区 |
| 最近报送 / 历史行 ⋮ | 查看报送依据、查看当时规划 | 固定快照和 revision；不跳到当前版冒充当时版本 |
| 支撑商机 ⋮ | 打开工作台、检视预测 | 保留商机及有效周期范围；分类调整沿用原权限 |
| 风险/缺口入口 | 查看明细 | 证据与受影响商机进入抽屉；主区不铺长段检查结果 |

双向链接拟扩展现有路由，以下是待实现契约，当前不能宣称已支持：

- 规划到执行：`/attainment?period=2026Q4&scope=territory:<id>&view=progress`。
  来自历史规划时增加 `planRevision=<revision-id>`，仅作只读来源上下文；显式提示当前执行仍按
  生效版，不能悄悄把历史版本变成当前考核基准。历史成绩须再指定实际快照。
- 执行回规划：`/planning?year=2026&region=<id>&revision=<revision-id>`；未选区域时省略 region。
  无版本读取权限时拒绝定位并说明；不能回退成展示全公司当前版。个人配额沿用现有个人入口。
- 历史复盘：现有 view=history 增加 `snapshot=<snapshot-id>`，必须匹配授权 scope/period；
  分享链接和刷新均固定该记录。不传时默认最近一次，并在界面明确所选时间。
- query 不授予权限，不提供任意 workspace 切换；重复/无效/不匹配参数显式拒绝或提示。
  查不到指定快照/版本不能静默显示另一份。抽屉关闭返回原筛选，跳转保留上下文。

按钮统一 32px、紧凑项 24px，三点菜单 32px / 图标 20px，使用 DS token。主标题下虚线
保留内容 padding；同页两级标题图标不重复。菜单只列可执行动作或清楚解释禁用原因，不能有空操作。
所有修改保留确认/失败输入/成功刷新与权限校验；浏览默认只读。历史与依据均进入抽屉。

### 7. 空态、权限与助手

| 情况 | 展示与操作 |
| --- | --- |
| 首版仍为草稿或待生效 | 显示尚无生效规划及预定生效时间；有权者查看规划，执行商机仍可见 |
| 已有旧正式目标但尚未接管 | 清楚标为旧目标来源，继续可用；不伪装成 V1，也不因无新规划抹去原目标 |
| 本区或本周期未设目标 | 无目标状态，有权者定位规划；保留真实成交与预测入口 |
| 有目标无报送 | 当前进度正常，报送行提示尚未提交，不能显示报送率 0% |
| 有报送但无目标依据 | none 显示当时未设目标；旧无绑定显示旧口径，不能借用今天的分母 |
| 配置区域已删除/改名 | 使用已发布范围及快照名称，提示配置变化；不猜替代区域 |
| 数据读取失败或币种冲突 | 展示错误与重试/逐币种信息，隐藏受影响比率，不能回退演示数字 |
| 仅有局部范围或客户/人员无权限 | 服务端裁剪可读投影；不泄漏全公司总额、隐藏行数量、姓名或预算 |
| 未订阅高级预测 | 基本进度可用；检视/历史/提交沿用既有权益门，不能通过新菜单绕过 |

右侧助手首期只引用经过授权的事实和确定性缺口。通用问答仍明确是通用上下文，不能假装已经
自动绑定所选周期、区域或版本。专属上下文后续须传递同一 selection、observationAt 与依据 ID，
回答附目标版本、商机证据和数据时点；切换筛选终止旧分析或标记旧上下文，历史视图不拿当前事实
替代历史。未连接模型时只提供规则提示，不承诺预测结论或自动调整规划。
