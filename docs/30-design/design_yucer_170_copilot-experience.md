# 智能助手：上下文、建议与连续对话

日期：2026-10-28。产品依据：20-specs/20-capability-domains.md D8、ADR-003、ADR-015。
本轮用户优先级：有依据且可执行的建议 + 连续对话体验。

## 现状判断

智能助手已有真实的 Atlas 模型调用、Runos 只读工具循环、证据检索、剧本、
agent_session/message 持久化、建议裁决与执行，并非全静态模型。
主要缺口在业务上下文与交互闭环，不能只用视觉包装解决。

| 环节 | 分析发现 | 本轮调整 |
| --- | --- | --- |
| 对象上下文 | 客户/商机入口恢复用户最近会话，未按对象过滤 | 严格按对象类型与 ID 恢复、切换历史 |
| 会话权限 | 续聊仅查 workspace，未检查 actor | 同步与流式路径检查本人会话；拒绝跨对象复用 |
| 无权访问对象 | 指定对象不可读时悄悄退化为通用问答 | 页面禁发；服务端拒绝，不带错上下文调用模型 |
| 侧栏入口 | 打开完整对话丢失当前对象 | 保留客户/商机锚点；仅有提问权限也可输入问题 |
| 发送状态 | transition 未等待 Promise，异常未捕获 | 等待完整请求、同步防重、失败恢复草稿 |
| 对话阅读 | 内容缺少角色、分段和边界 | 角色、保留换行、可滚动日志、新对话和预填问题 |
| 建议处理 | 生成数量无明确处理入口 | 跳到建议队列，成功后刷新服务器数据 |
| 权限退化 | 无建议读取权限会阻断整个页面 | 对话与建议读取失败分别展示 |
| 建议质量 | 已有不编造要求，但输出行动约束较弱 | 要求依据、事实/推断区分、缺失信息、有限具体行动 |
| 空壳控件 | 默认竞争情报占位、无附件处理器仍展示按钮 | 默认不展示竞争情报占位；有处理器才展示附件 |

## 验收边界

1. 同一客户或商机可以连续追问、选择该对象的历史、开启新对话；不同对象不共享历史。
2. 他人的会话 ID、不同对象的会话 ID 不得产生追加消息、模型调用或轮次记账。
3. 提问不会因连续点击重复发送；服务器异常显示反馈并恢复输入。
4. 建议保留独立人工裁决。聊天中不新增一键接受，不绕过权限、订阅或执行门禁。
5. 推荐问题仅预填，用户点击发送才使用模型配额。

## 明确尚未解决的能力

- 当前聊天仍为整轮返回。已有 SSE 路径只支持不含建议工具循环的普通对话，
  不能直接接入带客户/商机证据与建议的页面；需要统一事件协议、取消与部分结果持久化后再接。
- 首轮模型失败前服务端已经保存问题并记账。客户端恢复草稿供手动重试，
  但新会话失败结果目前不返回 session ID；不能声称重试免费或完全幂等。
- 历史目前读取最近 50 个本人会话，并展示当前对象最近 8 个入口；不是完整会话管理器。
- 证据引用仍为文本 ID/标签，不是可点击引用卡片；尚未进行真实销售样本的建议质量评测。
- 本轮提示约束不等于模型质量保证。上线前应以有记录、记录稀少、记录冲突、
  无权限四类样本人工核对依据、建议可执行性、缺失信息提示和越权情况。
- 负责人团队风险与承诺视角保留为后续业务能力，当前不新增未接数据的仪表盘。

## 下一阶段实施顺序

先补失败轮次恢复与幂等重试，再把证据来源做成可追溯链接，并以真实样本评测。
随后统一带工具调用的流式事件协议，最后扩展团队任务和承诺风险建议。

## 右侧栏布局与授权入口补充

右栏使用完整可用高度；顶部固定智能模式选择，下方助手区域伸缩。
无有效推进/裁决条目时不渲染空队列，输入区填满剩余空间。
存在有效条目时，输入区收缩并保留最小编辑高度，下方条目可滚动查看；
窄高视口允许内部滚动，不截断操作按钮。

智能模式复用工作区 agent_autonomy：全权授权（autonomous）、常规授权
（ask_high_risk）、逐项确认（ask_always）。读取与修改均沿用服务端门禁，
更改由当前登录者签名，不使用浏览器存储模拟授权。成功后刷新全局布局。
全权授权不承诺执行尚无 handler 的动作，原有执行与订阅门禁保持有效。
