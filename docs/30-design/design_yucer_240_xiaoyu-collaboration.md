# 小聿：统一协作、记忆与能力调度设计

上游权威：[37-xiaoyu-collaboration](../20-specs/37-xiaoyu-collaboration.md)。
状态：目标设计，未实施；不以此文代替 DDL、权限目录、接口或真实模型验收。

## 一、现状与复用

| 当前实现 | 复用与缺口 |
|---|---|
| agent_session / agent_message | 已持久化，但本人及固定 subject 校验不能直接支持多对象任务；保留旧边界，新模型单独设计 |
| 表单助手与 CopilotChat | 共用部分调用链，但会话与草稿状态分散；需要统一会话和任务生命周期 |
| 首页 judgementFeed | 有跨域规则与证据；作为小聿主动议题来源，保留权限与确定性计算 |
| Header G5 / ShellDock | 复用入口与 DS 窄／宽模式，完整工作区与页面协作栏使用同一会话 |
| Atlas routes / profiles | 已有目录、容量与四类调用档位；需要按任务规划与已授权路由组合映射 |
| Runos discover / resolve / invoke | 已可动态加载、分页枚举与加载 Skill；仍须补业务任务编排和执行闭环 |
| agent_action / executor | 保留不可变提案、域服务及审计；任务级授权、幂等与恢复关联 #652 |

实现应新增明确的任务与上下文层，不通过删除原有 actor／subject 校验制造“共享历史”。
个人对话可被本人检索，但不同客户事实不能在恢复会话时无标识地混入另一个客户。

## 二、逻辑结构与对象归属

入口／展示 → 统一会话与任务编排 → 上下文装配 → Atlas 推理与 Runos 能力 → 域服务／执行回执。
记忆、知识和来源验证服务在上下文装配及成果交付前共同参与。

以下为逻辑对象，字段和表名须在实施批次另行设计、DDL 与 Prisma 同步，全部内部关联使用 UUID：

| 对象 | 隔离与内容 |
|---|---|
| 个人会话与消息 | workspace + owner，原始聊天及工具结果，不提供团队读取路径 |
| 个人任务 | workspace + owner，多对象 UUID、目标、草稿、检查点、授权引用；派生笔记保持私有 |
| 私人记忆 | workspace + owner，来源、类别、有效期、状态、替代版本，不设团队共享字段 |
| 共享业务知识 | workspace + 独立知识对象 ACL + 来源权限；不含聊天原文、摘要或私人记忆引用 |
| 来源与依赖记录 | 对象 UUID、版本、权限范围、失效状态；支持定位并失效所有派生项 |
| 执行记录 | 任务、提案、实际调用、对象版本、幂等键、结果与失败；按业务权限展示 |

业务事实仍由原业务域拥有；小聿的记忆是有来源的辅助读模型，不能成为业务主数据副本。
共享知识由合法业务来源产生；从私人对话另存知识须独立预览及保存，只带审阅后的业务内容。
团队共享任务成果也不能连带开放个人会话或任务笔记。

## 三、检索与失效

1. 服务端解析身份与工作空间，建立本次权限及任务范围，拒绝页面或模型自报的越界空间。
2. 在存储查询与候选检索阶段限定空间、本人和来源范围；向量候选也必须受约束。
3. 分别检索本人记忆与合法业务知识，装载内容时再次检查来源权限、停用状态和版本。
4. 与当前有效业务数据对齐，区分已发布、未发布草稿、历史版本、推断和假设。
5. 仅将相关且合法的信息装入本轮上下文，保留可见来源，不能用摘要掩盖来源不可读。
6. 工具动作执行和结果交付前重新校验；权限发生变化时取消或重新构建上下文，不能继续用旧内容作答。

缓存键包含 workspace、owner／可见性范围、权限修订、来源版本及记忆状态修订。
业务知识改变 ACL、源对象撤权、本人停用记忆时，同步提高修订并使已缓存检索、摘要和任务检查点失效。
异步清理索引可用于资源回收，但不作为即时撤权屏障；清理完成前，读取路径已必须拒绝。
恢复长任务与流式输出须校验有效授权；无法核验时不交付受限内容。
不得把私人记忆注入其他人的共享会话、系统级摘要或跨工作空间模型缓存。

纠正使用替代版本，旧条目退出召回；停止使用同时作用于其派生摘要，不能通过回放压缩上下文重新引入。
查看原始历史、纠正记忆与删除记录是不同动作；不得承诺物理删除却只改一个隐藏标记。

## 四、入口与连续交互

Header G5 在已登录产品壳内常驻。平台工作区保留 Header；主区默认为今日议题和输入区，
最近对话与进行中任务置于可收起左栏，资料／成果在需要时展开。复用 /copilot 路由的迁移需保留旧链接。
不同时展示两套对话输入；页面上下文只作当前查看对象提示，不覆盖任务目标。

页面操作打开同一小聿的协作栏。前往业务页面、从侧栏回完整工作区时携带任务与会话引用，
服务端校验本人／空间归属；表单未保存内容作为私有草稿保留，人工改动有明确优先规则。
关闭窗口不等于取消任务；停止任务需要后台确认，刷新能恢复真实状态。

「记忆与知识」区按我的记忆、历史对话、共享业务知识分开呈现；私人项没有共享按钮。
记忆查看页显示来源、时间、类型、有效状态和纠正／停止使用入口，知识条目单独管理合法共享范围。

## 五、Atlas 与 Runos 能力使用

产品侧定义任务类型与质量需求，Atlas 决定 endpoint 后的模型和回退链。
先核对获授路由、容量、状态、支持的模态及推理参数，再设计对话、复杂规划、结构化草稿、
提炼、评分、向量和重排等任务映射；不能把全部 12 个路由都按同一接口盲调。
现有路由与参数策略需明确迁移，不把旧四类档位视为平台上限，也不无条件选昂贵模型。
任务预算覆盖输出、工具结果、检索、总耗时与计量；足够完成已授权任务，并可继续或恢复，
不能因低固定轮次截断而将未完成的业务报告为完成。

Runos 先发现相关能力，再解析受控版本和真实输入输出，按需加载 Skill 及依赖。
目录分页需完整处理；失败应区分未获授、停用、缺失依赖、超时、结果为空和契约错误。
Skill 文本带来源围栏和摘要校验，不能更改系统约束、授权范围或隐私边界。
Skill 指导、连接器实际结果和域服务保存回执分别记录，不能把“加载成功”写成“任务完成”。
调用链使用稳定 taskId；记录路由、能力版本、callId、耗时、用量及真实业务 UUID，
诊断日志不携带私人聊天、记忆正文或凭据。平台通用能力目录元数据可以产品级缓存，
工作空间票据、调用输入结果和记忆内容不能因此使用全局缓存。

缺能力先核对目录与实际权限，再在 Runos 提交可复用能力契约及验收；消费者 Issue 引用平台 Issue、
实现 PR、发布版本和实调证据。只有确认有平台缺口时才提单，不因未经核验的空结果要求用户重新授权。

## 六、实施前提

### 执行契约与服务端屏障

读取链：已验证会话 → 任务与对象范围 → 受控业务查询 → 当前有效记录／明确标注的草稿。
修改链：分析结果 → 版本化字段契约 → 私有表单草稿／页面回填 → 校验与确认 → 原域服务 → 真实回执。
页面不是读取事实的唯一来源；数据库由业务查询服务读取，模型没有数据库连接或任意 SQL 入口。
后台草稿与页面使用同一字段契约，不另建绕过表单校验的 agent 写入通道。

系统执行契约具有版本标识，在新回合、恢复检查点和 Skill 装载时装配；任务持久化记录使用的版本。
实际执行以前由服务器获取当前版本并检查工具种类、workspace、owner、对象范围、动作、权限、
任务授权、期限、撤销状态、对象版本及幂等键。上下文中的规则文本只作指导，不充当授权。
升级不兼容、权限变化或来源失效时拒绝旧步骤或重新准备，不能靠模型复述“我已遵守”。

受控查询、字段回填、保存及发布分别登记能力状态。人工修改有字段来源／修订信息，
回填不能覆盖后来的人工作业；提交通过原业务服务的 entitlement + permission 双门。
返回 UUID、版本与可打开入口才可声称保存完成；发布还需独立发布回执。
审计保留执行契约版本与实际拒绝／执行结果，私人内容不得流入公共诊断。

XY-01A 先交付契约版本及隔离拒绝路径；04A、04B 分别补具体适配和提交，复用 #652。
必须验证对话／Skill 要求绕过表单、任意 SQL、切换空间、沿用旧授权、伪造成功和撤权缓存复用，
不以提示词快照测试代替调用服务端真实拒绝路径的测试。

本期不新增跨空间共享、不将聊天转团队记忆、不绕过三档授权或 ADR-003/004。
执行侧缺口由 #652 与 XY-04 联动；未完成任务级保护的动作不得先开放无人值守处理。
每批次以失败反例和真实服务回执验收，跨平台能力必须提供真实调用证据；夹具测试不能代替。
