# 小聿：统一协作、记忆与能力调度设计

上游权威：[37-xiaoyu-collaboration](../20-specs/37-xiaoyu-collaboration.md)。
状态：任务／个人记忆与执行底座已有生产验证；双区协作工作区按最新 owner 要求本地预览中，知识平台待接入。
不以此文代替 DDL、权限目录、接口或真实模型验收。

## 一、现状与复用

| 当前实现 | 复用与缺口 |
|---|---|
| agent_session / agent_message | 已持久化，但本人及固定 subject 校验不能直接支持多对象任务；保留旧边界，新模型单独设计 |
| 表单助手与 CopilotChat | 共用部分调用链，但会话与草稿状态分散；需要统一会话和任务生命周期 |
| 首页 judgementFeed | 有跨域规则与证据；作为小聿主动议题来源，保留权限与确定性计算 |
| Header G5 / ShellDock | 复用入口与 DS 窄／宽模式，完整工作区与页面协作栏使用同一会话 |
| Atlas routes / profiles | 已有目录、容量与四类调用档位；需要按任务规划与已授权路由组合映射 |
| Runos discover / resolve / invoke | 已可动态加载、分页枚举与加载 Skill；仍须补业务任务编排和执行闭环 |
| agent_action / executor | 保留不可变提案、域服务及审计；任务级授权、幂等与恢复关联 #652 |

实现应新增明确的任务与上下文层，不通过删除原有 actor／subject 校验制造“共享历史”。
个人对话可被本人检索，但不同客户事实不能在恢复会话时无标识地混入另一个客户。

## 二、逻辑结构与对象归属

入口／展示 → 统一会话与任务编排 → 上下文装配 → Atlas 推理与 Runos 能力 → 域服务／执行回执。
记忆、知识和来源验证服务在上下文装配及成果交付前共同参与。

以下为逻辑对象，字段和表名须在实施批次另行设计、DDL 与 Prisma 同步，全部内部关联使用 UUID：

| 对象 | 隔离与内容 |
|---|---|
| 个人会话与消息 | workspace + owner，原始聊天及工具结果，不提供团队读取路径 |
| 个人任务 | workspace + owner，多对象 UUID、目标、草稿、检查点、授权引用；派生笔记保持私有 |
| 私人记忆 | workspace + owner，来源、类别、有效期、状态、替代版本，不设团队共享字段 |
| 共享业务知识 | workspace + 独立知识对象 ACL + 来源权限；不含聊天原文、摘要或私人记忆引用 |
| 来源与依赖记录 | 对象 UUID、版本、权限范围、失效状态；支持定位并失效所有派生项 |
| 执行记录 | 任务、提案、实际调用、对象版本、幂等键、结果与失败；按业务权限展示 |

业务事实仍由原业务域拥有；小聿的记忆是有来源的辅助读模型，不能成为业务主数据副本。
共享知识由合法业务来源产生；从私人对话另存知识须独立预览及保存，只带审阅后的业务内容。
团队共享任务成果也不能连带开放个人会话或任务笔记。

## 三、检索与失效

1. 服务端解析身份与工作空间，建立本次权限及任务范围，拒绝页面或模型自报的越界空间。
2. 在存储查询与候选检索阶段限定空间、本人和来源范围；向量候选也必须受约束。
3. 分别检索本人记忆与合法业务知识，装载内容时再次检查来源权限、停用状态和版本。
4. 与当前有效业务数据对齐，区分已发布、未发布草稿、历史版本、推断和假设。
5. 仅将相关且合法的信息装入本轮上下文，保留可见来源，不能用摘要掩盖来源不可读。
6. 工具动作执行和结果交付前重新校验；权限发生变化时取消或重新构建上下文，不能继续用旧内容作答。

缓存键包含 workspace、owner／可见性范围、权限修订、来源版本及记忆状态修订。
业务知识改变 ACL、源对象撤权、本人停用记忆时，同步提高修订并使已缓存检索、摘要和任务检查点失效。
异步清理索引可用于资源回收，但不作为即时撤权屏障；清理完成前，读取路径已必须拒绝。
恢复长任务与流式输出须校验有效授权；无法核验时不交付受限内容。
不得把私人记忆注入其他人的共享会话、系统级摘要或跨工作空间模型缓存。

纠正使用替代版本，旧条目退出召回；停止使用同时作用于其派生摘要，不能通过回放压缩上下文重新引入。
查看原始历史、纠正记忆与删除记录是不同动作；不得承诺物理删除却只改一个隐藏标记。

## 五、Atlas 与 Runos 能力使用

产品侧定义任务类型与质量需求，Atlas 决定 endpoint 后的模型和回退链。
先核对获授路由、容量、状态、支持的模态及推理参数，再设计对话、复杂规划、结构化草稿、
提炼、评分、向量和重排等任务映射；不能把全部 12 个路由都按同一接口盲调。
现有路由与参数策略需明确迁移，不把旧四类档位视为平台上限，也不无条件选昂贵模型。
任务预算覆盖输出、工具结果、检索、总耗时与计量；足够完成已授权任务，并可继续或恢复，
不能因低固定轮次截断而将未完成的业务报告为完成。

Runos 先发现相关能力，再解析受控版本和真实输入输出，按需加载 Skill 及依赖。
目录分页需完整处理；失败应区分未获授、停用、缺失依赖、超时、结果为空和契约错误。
Skill 文本带来源围栏和摘要校验，不能更改系统约束、授权范围或隐私边界。
Skill 指导、连接器实际结果和域服务保存回执分别记录，不能把“加载成功”写成“任务完成”。
调用链使用稳定 taskId；记录路由、能力版本、callId、耗时、用量及真实业务 UUID，
诊断日志不携带私人聊天、记忆正文或凭据。平台通用能力目录元数据可以产品级缓存，
工作空间票据、调用输入结果和记忆内容不能因此使用全局缓存。

缺能力先核对目录与实际权限，再在 Runos 提交可复用能力契约及验收；消费者 Issue 引用平台 Issue、
实现 PR、发布版本和实调证据。只有确认有平台缺口时才提单，不因未经核验的空结果要求用户重新授权。

### 内部业务查询的上下文边界（2026-11-24）

- `query_business`先经过原域服务、本人权限和工作区范围，再按UUID稳定排序、筛选和分页；默认10项，单页最多20项，实际页长可随内容缩小。
- 单次回执按现有估算器控制在2400 tokens内。列表仅提供关键字段预览，保留数值、时间、状态和完整记录的来源版本；不能把截短后的JSON作为新事实版本。
- `matchedCount`只统计当前有权读取且符合筛选的记录，`nextOffset`用于继续读取。`truncatedPaths`明确标出文本、数组或嵌套结构的省略；局部页不能支撑全量统计或“没有推进”的结论。
- 指定对象UUID与`fields`可定点读取；路径只允许自身属性和数组索引，禁止原型链、表达式及通配。单个长文本字段通过`textPage.nextOffset`继续读取，不能永远只看到开头。
- 销售规划默认列表不载入全部历史修订；通过`availableFields`与`arrayLengths`导航所需版本。客户表单契约中的关联市场仅返回UUID和名称，市场正文仍走受控业务查询。
- 查询前后来源和权限重新核验、来源数量与任务总预算维持原限制。刷新历史失败回合仍显示具体原因；恢复动作仅填入原问题，已有新输入时不显示，不自动重跑模型或业务操作。
- 单页限额不能代替多轮累计控制。同一回合的原生查询回执共用动态上下文额度，最多6000估算tokens；根据剩余总预算进一步收窄。优先收敛较早的页，保留近期详情、精确数值、来源版本、分页与定点续读方式；省略字段、正文或来源索引均须显式标记，不能从摘录推断全量结论。
- 收敛仅作用于本回合送模型的原生查询数据；系统约束、用户原话、模型续接签名、工具协议ID和私有表单保持原样。完整来源闭包仍由服务端保存并重新核验，不因模型侧省略而减少撤权／版本检查；原始回执只在本回合私有内存中存在，不转为个人记忆或团队知识。
- 在追加查询可能用尽总预算前，预留一次基于现有证据的回答并关闭本次请求的工具。回答明确未读页、缺失信息和未完成步骤；持久化与重放均保留`incomplete`状态。模型仍返回工具调用时服务端拒绝执行，不能靠提示词放宽执行边界。总token、时间、调用数和来源数限制维持原值。

## 六、实施前提

### 执行契约与服务端屏障

读取链：已验证会话 → 任务与对象范围 → 受控业务查询 → 当前有效记录／明确标注的草稿。
修改链：分析结果 → 版本化字段契约 → 私有表单草稿／页面回填 → 校验与确认 → 原域服务 → 真实回执。
页面不是读取事实的唯一来源；数据库由业务查询服务读取，模型没有数据库连接或任意 SQL 入口。
后台草稿与页面使用同一字段契约，不另建绕过表单校验的 agent 写入通道。

系统执行契约具有版本标识，在新回合、恢复检查点和 Skill 装载时装配；任务持久化记录使用的版本。
实际执行以前由服务器获取当前版本并检查工具种类、workspace、owner、对象范围、动作、权限、
任务授权、期限、撤销状态、对象版本及幂等键。上下文中的规则文本只作指导，不充当授权。
升级不兼容、权限变化或来源失效时拒绝旧步骤或重新准备，不能靠模型复述“我已遵守”。

受控查询、字段回填、保存及发布分别登记能力状态。人工修改有字段来源／修订信息，
回填不能覆盖后来的人工作业；提交通过原业务服务的 entitlement + permission 双门。
返回 UUID、版本与可打开入口才可声称保存完成；发布还需独立发布回执。
审计保留执行契约版本与实际拒绝／执行结果，私人内容不得流入公共诊断。

XY-01A 先交付契约版本及隔离拒绝路径；04A、04B 分别补具体适配和提交，复用 #652。
必须验证对话／Skill 要求绕过表单、任意 SQL、切换空间、沿用旧授权、伪造成功和撤权缓存复用，
不以提示词快照测试代替调用服务端真实拒绝路径的测试。

本期不新增跨空间共享、不将聊天转团队记忆、不绕过三档授权或 ADR-003/004。
执行侧缺口由 #652 与 XY-04 联动；未完成任务级保护的动作不得先开放无人值守处理。
每批次以失败反例和真实服务回执验收，跨平台能力必须提供真实调用证据；夹具测试不能代替。


## 七、XY-01A 已实现的数据与运行契约

结构权威：`incr/0133_xiaoyu_task_foundation.sql`，Prisma 仅镜像；实现及验收见
[116 任务底座记录](../70-workplan/116-xiaoyu-task-foundation.md)。这些对象属于 D8，未新增商业功能键或成员角色。

| 对象 | 内容与不可变边界 |
|---|---|
| agent_session.kind | legacy／task，不可修改；旧会话原 actor／subject 不变 |
| agent_task | workspace＋actor；不可变目标、创建请求及指纹、独立任务会话；可变状态、规则版本、修订和页面提示 |
| agent_task_reference | 追加式来源依赖闭包：对象 UUID、类型、版本指纹及 target／context／legacy 角色；清除当前页面不撤除历史来源检查 |
| agent_task_session | 引用同空间本人的旧会话；history_policy 固定 excluded，不复制或装载旧聊天 |
| agent_task_draft | 追加式 private-notes/1 快照；每键读取最新修订，业务表单契约留给 04A |
| agent_task_checkpoint | 追加式任务修订、规则版本、消息序号；不保存任意执行脚本或可复用授权 |
| agent_task_turn | 每请求唯一回执，running／succeeded／failed／interrupted；问题指纹与消息 UUID 不可变，终态不可改写 |

全部内部记录关系使用 UUID；复合外键附带的 workspace、OIDC actor_sub 和会话种类用于拒绝跨空间、
跨本人及旧／新会话混连，不用名称或业务编号作关联。旧消息不回写。六张新表没有服务角色 DELETE 权限，
引用、草稿、检查点没有 UPDATE 权限；任务和回执只授予列级更新，Prisma 更新同步经过列锁断言。

创建会话、任务、来源与初始检查点在同一事务中提交。创建请求按空间、本人、requestId 唯一；
不可变指纹绑定最初目标和对象集合，之后新增关联不会放宽原请求重放。任务修改通过修订 CAS；
模型调用不占用数据库事务。回合准入、问题写入及运行回执原子提交，完成时原子写入回答、终态与检查点。
每任务只有一个 running 回执，终态重复请求只返回原回答，不重新计量或调模型。失败／中断不自动重试，
持久化的孤儿 running 回执可在会话锁释放后显式标记中断，再以新请求继续。

接口为 `/api/copilot/tasks`、`/api/copilot/tasks/[taskId]` 与后者的 `/turn`。
工作空间和本人由服务器当前会话取得，不接受请求体声明；管理员无他人私人任务读取特例。
先取得本人元数据并核验全部来源，再加载消息和笔记；交付模型结果前重新获取当前登录、产品授权、
本地权限和数据范围，绕过请求级／进程级授权缓存。模型结果持久化与交付分别核验，失效时拒绝交付。
跨站修改请求、超出 32 KiB 的实际请求体、伪造字段和未知操作均拒绝，私有结果禁止共享缓存。

01A 的来源解析只返回对象身份和版本指纹，不向模型提供业务字段正文。新任务只开放对话、私有笔记和
任务状态操作，不装载 Runos 工具；模型即使返回 SQL、Skill 或其他工具调用，服务器也拒绝。
系统提示包含当前 xiaoyu/1 契约；旧规则任务须显式 resume 后重新核验，检查点不能自己选择版本或授权。
同一 taskId 传给 Atlas 和 Runos 上下文，但本批不执行 Skill，也不计作 Skill 调度验收。

来源当前版本变化时先返回 source_changed，不继续回放旧上下文；自动重建来源、按消息细分失效及
来源内容受控查询留给 02／04。存量旧聊天的自动迁移覆盖率为 0：保留原入口和来源锚点，
新任务只引用归属且排除其原文，不能声称已完成跨历史会话召回。完整界面和真实本人 OBO 续接在预览 A 验收。

## 八、任务驱动的共用面板与页面理解（设计补充，HTML 阶段）

本节落实上游规格第七节；本轮只更新文档与独立 HTML，不修改产品组件、接口或数据库。

### 状态与范围

- 全局任务控制器持有任务、对话、输入、步骤、业务草稿和逐项执行回执；不按 pathname 重建。
- 页面上下文由模块注册：pageKind、module、object、version、selection、filters、formContract、
  currentValues、dirtyFields、validation、capabilities。仅提交本轮必要字段，私人草稿不进入共享知识。
- 当前焦点单独保存 kind、引用、显示名称、来源（页面／对话／人工）、更新时间及解除状态。
  页面自动线索不能覆盖用户刚解除的同一焦点；有明确新讨论或新对象时可重新聚焦。
- 每次回合固定上下文快照；提交另固定目标、字段差异、来源版本与授权。切页不重定向运行步骤，

## XC 实施约束与接口（2026-11-24）

- `page-context/1` 从86页正式清单投影语义；静态路由优先于动态对象路由。筛选仅接受白名单键及有界字符串，选中对象最多20个，服务端重新逐项校验权限／版本。页面上下文与实际工具授权分别检查。
- `XiaoyuFormReview` 复用原服务端页面与客户端字段组件；`useXiaoyuForm` 同步私有草稿，原提交入口在复核容器内被截断为草稿同步。执行准备前排空同步并重新取得不可变草稿UUID。客户真实创建与回执在同一事务，采用原编号分配锁，避免并发重复。
- 每日基线通过 Redis SET NX／三日过期维护；键含工作区、本人、数据范围、权限指纹、上海业务日。保存内容仅为摘要哈希；列表每次重新读取现行授权来源。后台先查基线是否存在，避免同日重复计算；部署端持久化不可用时标明降级，不能假称已生成每日快照。

- `/api/copilot/tasks/[taskId]/export` 返回 private no-store 的Markdown附件，正文以安全代码围栏隔离，前后两次核验当前访问与任务版本。未发输入和技能控制项排除。

## 九、页面与智能体共用的服务端业务边界（2026-11-25）

上游为规格“统一业务接口与数据库边界”。BFF 是前端／工具适配职责，域服务是唯一业务规则与持久化职责；
同进程入口可以直接调用服务，不为共用而增加自调 HTTP，也不新增一个可供模型使用的数据库代理。

| 层 | 当前入口／职责 | 不可越过的边界 |
|---|---|---|
| 页面 | 原生 Server Actions、私有任务 forms／execution HTTP | 展示业务名称和待处理项；不能自行认定权限或声称未取得的写入成功 |
| 智能体工具 | query_business、business_form_contract、prepare_business_form、request_business_execution | 仅注册操作和字段；不接受任意 SQL、表名、工作空间或所有者声明 |
| 服务端适配 | taskRequestContext、businessBindings、表单／执行 handler | 当前身份、权益、数据范围、字段契约、来源、名称解析和安全格式规范化 |
| 业务与执行 | 原域 service、execution-service、writeBusinessForm | 版本、人工保护、授权快照、幂等与真实回执；规则由域服务决定 |
| 持久化 | Prisma 域 store、执行事务与来源闭包 | 仅服务端可访问；不能把驱动异常或原 SQL 参数送给模型／页面 |

页面与工具可使用不同传输协议，但不能具有两套保存语义。当前已共用域服务；
统一“字段问题／建议修正／需确认／可重试／部分完成”结果契约仍按模块推进，不能宣称全站已迁移。
服务端先进行可解释的结构与业务判断；模型可建议映射和补齐，不能最终裁决权限、覆盖或冲突。

### 来源身份和查询闭包

销售规划投影目标不对应单独 sales_target 行，原先的 plan_ 前缀键不能写入 UUID 来源列。
投影在所属规划域统一产生 SHA-256 UUIDv8：命名空间版本＋工作空间＋规划根＋行键；
查询返回、定点读取、来源重读和任务存储使用同一身份，不在存储阶段临时替换 UUID 或丢弃该来源。
身份独立于金额和修订值；已有接管目标沿用真实数据库 UUID，来源版本仍根据当前业务内容及达成口径变化。
旧投影键仅保留为今日判断／暂缓的兼容锚点，不作为任务来源或写入目标。

投影仍标记 managedBySalesPlan；页面接管筛选、旧目标写入口和 store 层均按这个属性保护，
不能因为改成 UUID 就误认为可通过旧目标表编辑／删除。没有新增业务行、DDL 或数据迁移。
工具结果绑定前检查来源对象契约；非法来源在模型继续读取及最终存储前拒绝，
保留明确错误与私有失败状态，不以忽略来源来放宽权限和版本依赖。

### 分析与私有表单的受控收尾（2026-11-25）

- 分析正文和服务端操作状态分别处理。既有记录的“已发布”等描述不能触发整篇替换；只纠正明确声称本轮已操作的语句，保留事实、Markdown、来源和建议。模型说法不建立业务回执。
- 由任务服务显式开启私有表单收尾；读取预算收敛后，只提供 prepare_business_form，模块枚举来自本轮成功返回的原生表单契约，不由模型／Skill／参考材料自行扩权。
- 收尾仅一批调用。执行前检查整批工具及模块；夹带查询、能力发现、导航、执行请求或未知模块时，整批拒绝。原有总调用、总 token、截止时间限制不变。
